# 公開リポジトリの設定点検

日本語 | [English](releasing.md)

現在の運用は、所有者一人が保守し、外部からの PR を受け付けない構成です。誰でも閲覧・fork・Issue 作成ができますが、信頼する履歴への書き込みは所有者に限定します。公開時は保護された main と CI を通し、専用の公開ワークフローを使います。

`tools/check_public_release_readiness.py` はこの運用モデルを検査します。保守者や参加方法を変える場合は、検査を弱める前に脅威モデルを見直します。

## 参加と書き込みの境界

- [ ] リポジトリは公開。
- [ ] `pull_request_creation_policy = collaborators_only`。
- [ ] 所有者以外の直接の共同作業者はいない。
- [ ] 外部利用者は上流へ PR を作成できない。
- [ ] 不具合報告・議論用の Issue は公開可能。

外部 fork の PR を受け入れる以前の案から変更した構成です。外部 PR を有効にする前に、ワークフロー承認、トークン権限、シークレット、実行先、ワークフロー変更とレビューの責任を再評価します。

## main の保護

規則名は `Protect main`、対象は既定ブランチです。

- [ ] 規則を有効にし、例外となる実行者を設けない。
- [ ] ブランチ削除と force push を禁止する。
- [ ] main への変更は PR 経由にする。
- [ ] 新しい push の後は古いレビューを無効にする。
- [ ] 一人運用の間は `require_last_push_approval = false`。
- [ ] レビューの指摘を解決する。
- [ ] 最新の基点に対する必須 CI を要求する。

必須のチェック名:

```text
docs
workflow-policy
release-config
test (1.26.x)
test (1.27.x)
race
e2e
```

`gitleaks` の必須化も推奨します。必須にしない場合も専用のシークレット検査は維持します。

独立した承認者がいない一人運用では、`required_approving_review_count = 0` は明示的な例外です。最後の push をした人以外の承認も必須にすると、自分の PR を処理できません。外部 PR を禁止し、所有者以外の共同作業者がいない場合に限る例外であり、新しい書き込み権限を与える前に再設計します。

## リリースタグの保護

規則名は `Protect release tags`、対象は `refs/tags/v*` です。

- [ ] 規則を有効にし、例外を設けない。
- [ ] タグの削除・変更・移動と non-fast-forward の移動を禁止する。

一人運用では作成権限を別に制限していません。ただし、タグを作れるだけでは公開できません。公開ワークフローはタグと現在の main HEAD の一致を要求し、公開直前にも再確認します。共同作業者や公開ボットを追加する前に、タグ作成権限を再設計します。

## 公開先と実行環境

公開ジョブは `release` GitHub Environment を使います。一人運用では独立した必須承認者を設定しませんが、名前付きの権限境界として維持します。二人目を追加するなら、独立した承認と、対応していれば自己承認の禁止を設定します。

- [ ] リポジトリの self-hosted runner は0台。
- [ ] 通常 CI は許可した GitHub-hosted runner だけを使う。
- [ ] 認証情報、Incus・Docker・containerd 管理権限、内部ネットワーク権限を持つ永続的な Host をワークフローから選べない。
- [ ] 組織へ移す場合は、見える実行グループを再監査する。

特権 E2E のためだけに通常 CI へ永続的な実行機を加えません。必要なら別の信頼境界として設計します。

## 公開ワークフロー

- [ ] `repository_dispatch` が既定ブランチのワークフローを実行する。
- [ ] 要求したタグと現在の main HEAD が一致する。
- [ ] ビルド・テストは読み取り専用権限。
- [ ] 公開ジョブは分離し、必要最小限の権限にする。
- [ ] 公開直前に main・タグを再確認する。
- [ ] 成果物に GitHub／Sigstore 証明を付ける。
- [ ] 外部 Action は完全なコミット SHA に固定する。

公開要求と成果物検証の手順は[リリースの安全性](../security/release-security.ja.md)に記載します。

## 実際の設定を点検する

リポジトリルートで、規則・共同作業者・Environment・実行機を読める GitHub CLI 認証を使います。

```bash
python3 tools/check_public_release_readiness.py --repo SLktEx/Hacocoon
```

成功時は `PUBLIC RELEASE READINESS OK` です。警告は一人運用の設計上の選択や追加防御の推奨を示します。API 権限不足は `UNVERIFIED` とし、成功にしません。

外部 PR の有効化、共同作業者・保守者・ボットへの権限追加、実行機の追加、組織への移動、公開の起動方法や権限モデルの変更前に再監査します。
