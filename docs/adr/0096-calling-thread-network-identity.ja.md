# 呼び出しスレッドのネットワーク識別

[English](0096-calling-thread-network-identity.md) | 日本語

状態: 既存ネットワーク接続処理の修正を実装。

Linuxのネットワーク名前空間はスレッドに属する。既存接続処理はOSスレッドを固定し、検証済みguestの名前空間でsocketを作り、終了時にそのスレッドを破棄する。guestのスレッドをcontrollerの実行プールへ戻さない。

Host識別の照合は、呼び出し側controllerスレッドから`/proc/thread-self/ns/net`を開く。`/proc/self/ns/net`はプロセスの先頭スレッドを参照するため、そのスレッドが接続専用としてguest内にいる間、別のcontrollerスレッドがEnvの名前空間をHostと誤認し得る。開いたdescriptorは呼び出し時の名前空間を固定し、その後Goがgoroutineを別スレッドへ移しても変わらない。

既存のHost名前空間拒否、前後のprovider識別、固定procディレクトリ、PID再照合、専用スレッドの寿命を維持する。拒否された名前空間の再試行、照合の省略、全スレッドが先頭スレッドと同じ名前空間にいるという仮定は採用しない。

実機回帰では先頭以外のスレッドに独立名前空間を作る。従来処理は別スレッドの識別を返して確実に失敗し、修正後は呼び出しスレッドと一致する。既存の名前空間作成権限を使い、先頭スレッド・ネットワークPolicy・Host listenerを変更しない。この証拠は欠陥と修正の確認であり、過去のすべてのWindows `stream_denied`の原因を確定しない。導入後の並列再接続受入は分けて記録する。
