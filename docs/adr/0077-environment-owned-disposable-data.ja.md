# Environmentに属する使い捨てデータ

状態：採用、実装候補。[English](0077-environment-owned-disposable-data.md)

## 決定

全ての使い捨て子領域の所有者とコピー元を、共通のEnv・Workspace leaseと一括予約します。
Workspace・OCIの保持契約と混在させません。数を制限した名前付き領域に、配置先と元世代を記録します。
Coreは識別と遷移、Standardは信頼済み設定の選択、基盤アダプターは作成・配置・実体不在の確認を担当します。

未着手と作成依頼済みを区別します。空領域は検証前に作成成功を記録し、コピーは既存の完了記録・復旧を使います。
Env実体の完全な不在は共通ライフサイクルだけが判断・保存します。その記録で新しい子領域作成を禁止し、
共通の所有領域削除へ進みます。全ての子領域の不在が確定するまで親EnvとWorkspace leaseを保持します。
結果不明の基盤操作は復旧が必要なまま残し、再試行を理由に再実行・強制削除しません。
不在を記録したEnv名へ削除を再送しません。

元世代の記録だけで古い共通元を永久に保持しません。進行中のコピー予約は元を保持します。
追加データの契約を扱えない基盤やsnapshotは明示的に拒否します。
LinuxのEnv本体への配置と所有関係を確認する再開処理は実装候補です。Standardの対象選択は製品で未有効化です。

## 不採用案

別のキャッシュカタログとロックでは、子領域を残したままWorkspaceを解放する競合が生じます。
保持用OCIの一枠へ混ぜると寿命と接続権限が異なるデータを扱うことになります。
上位処理が下位の変更を個別に組み立てると、[ADR 0002](0002-environment-lifecycle-ownership.md)で防いだ途中状態を再導入します。
空の実体参照を不在とみなすこと、作成結果不明のまま削除すること、以前不在になった名前へ削除を再送することは、
無関係なデータの破壊につながります。snapshot・copy・transferで追加領域を省略すると、黙ってデータを失います。

[キャッシュ世代管理](../design/cache-generations.ja.md)の所有管理部分の決定です。
Host設定、レポ相対パスへの配置、停止済みEnvからの収集は残件です。

## 実体への配置の決定

custom volumeに親の作成識別子を記録し、Envの初期設定に全配置の組を記録します。
手動・クライアント起因の再開は同じ現カタログとleaseを使い、実体の不一致を拒否します。
追加領域付きEnvは実体名だけで再開しません。途中で配置が失敗しても、既存の共通処理がEnvと子領域の回収を担当します。

停止中のIncusファイル情報を上限付きで取得し、各親を検査し、配置先は未作成か空のEnv本体内ディレクトリに限定します。
保護対象パスと別diskの重なりを拒否します。Incus 6.0.5の`FileSFTPConn`は停止中のEnv本体だけをmountするため、
その応答を接続済みWorkspaceの内容確認とみなすと別のデータを検査します。
Env内ツールに安全性を証明させること、daemonのmountパスを推測すること、特権・shifted mountを有効化すること、
既存内容を黙って隠すこと、WSLのmount namespace差を理由に検査を弱めることは採用しません。
レポ相対パスは、この基盤境界の中で実際の対象を観測する処理が必要です。
