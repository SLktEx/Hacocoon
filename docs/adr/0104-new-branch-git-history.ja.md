# ADR 0104: 新しいGitブランチで公開済み履歴を再利用する

日本語 | [English](0104-new-branch-git-history.md)

状態: 実装方針を採用。導入済み環境での受入は別管理。

## 背景

[ADR 0102](0102-incremental-git-history.ja.md)の差分転送でも、新規ブランチには
全履歴を再送していました。既存の大きなレポで小さな変更をpushする通常の開発が、
packの上限で止まる原因になります。

## 決定

新規targetでは、一覧にあり、手元で新しいcommitの祖先と確認できるheadを一つ選びます。
登録したcheckoutのheadを優先し、ほかは最大31個まで調べます。既存の正確なrefのfetchを
head/OIDと同じOIDのhaveで要求します。brokerは新しい読み取り判断を行い、Hostは
そのrefを取得して一覧のOIDとの一致を確認し、読み取りキャッシュのrefで保持します。
手元には既に同じ履歴があるため応答のpackは空になり、その履歴を新規pushから省きます。

既存のStandard操作を組み合わせる変更です。Core契約、権限、認証情報、guestのpath、
共有書き込みレポは追加しません。pushの対象は元の新規ブランチのままで、旧OIDはゼロ、
新OIDは固定したcommitです。通常の準備時の読み取り確認、独立したpush承認、未存在を
要求するlease、実行記録・照合を維持します。基準の読み取り失敗、移動、不正な応答では
push前に停止し、別の読み取りや外部書き込みを自動で試しません。

## 制約と採用しない案

一覧取得を読み取りやpushの許可に変えたり、Host内の任意の隠れたOIDを選んだり、
古い一覧のrefを黙って使ったりしません。メモリ上限を任意のレポ容量まで広げません。
利用できる公開済みの祖先がなければ、従来の上限付き全体packを使います。新しいpack
自体が32 MiBを超える場合の転送は残件です。33 MiBの部品検証は履歴再送の修正を示し、
巨大レポ性能や導入後の認証付き利用を証明するものではありません。旧版互換や通信形式の
移行は追加しません。
