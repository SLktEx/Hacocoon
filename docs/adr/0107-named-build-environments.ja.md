# ADR 0107: 所有情報を変えずにビルドEnvへ名前を付ける

[English](0107-named-build-environments.md) | 日本語

状態: 実装方針として採用。導入済み環境での確認は別に残す。

## 問題と決定

ランダムなビルドEnv名では、通常の管理者用通信規則で対象を事前に指定できない。
依存取得のために全Env向けの規則を必要とすると、Packerの日常利用で範囲を絞りにくい。

Base定義に任意の `builder_name`、CLIに `--builder` を追加する。
要求の入口で通常Envと共通の名前検証を行う。省略時とarchive importは従来どおりランダム名を使う。
指定名も正規の新規作成処理だけへ渡す。作成が失敗した既存Envを再開・採用・置換・削除しない。

各試行は新しい一時Workspaceを作り、通常の作成IDとleaseを取得する。
実行・停止・公開・後始末ではその正確な所有情報を照合する。
名前は所有IDでも通信許可でもない。buildはPolicy設定を書き換えない。
管理者の名前指定規則は、意図的に同名の後続Envにも適用される。
通常の保存済みEnv承認は、その一回の作成IDへの紐付けを維持する。
HCLやshellがHost権限・資格情報を選ぶこともない。

## 採用しない方法と検証

広いallow規則の自動追加、取得URLからの許可推測、Host上のPacker実行、
同名という理由だけでの残存builder再利用は行わない。
名前指定の実装だけで、Packerの取得・build・作成したBaseの再利用が成功したとは扱わない。

CLI・controller・共通build経路への名前伝達、同名再試行時の新しい一時所有情報、
作成失敗後に削除しないこと、公開・cleanup失敗の保持、不正名の作成前拒否を回帰で確認する。
provider所有権は既存の同名衝突・逆操作・名前再利用のライフサイクル試験も引き継ぐ。
