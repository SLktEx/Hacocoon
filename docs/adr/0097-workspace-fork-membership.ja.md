# ADR 0097: Workspace複製時にレポ構成を選ぶ

状態: accepted
日付: 2026-09-15

## 決定

既存の停止Workspace複製・リポジトリ復元処理に、コピー先のレポ選択を追加します。
残すレポは正確な保存済み構成要素、追加レポは登録済みHostリポジトリを使い、同じ登録処理のロック内で扱います。
保存元の予約には完全なsnapshotの識別情報を使い続けます。選択した一部だけのsnapshotを作ったことにはせず、元の構成も直接変更しません。

全メンバーのコピー先を永続予約してからproviderへ作成を依頼します。
作成成功の記録を保存してから検査・初期化を実行し、Git初期化は追加レポだけに適用します。
既存の登録情報による参照が再起動後も追加元を保護し、保存元の共通予約がsnapshotを保護します。
OCI復元の完了前には公開しません。削除結果が不明な場合は所有権と保存元の保護を残します。
RestoredFromは作業全体の複製元を表し、Hostから追加したメンバーがある場合も同じです。

## 採用しない方式

使用中の構成を直接変更するとleaseが指すパスが変わります。
workflowやcontrollerで別のコピー処理を作ると作成・削除判断が重複します。
既存レポの再cloneは未コミット変更やindexを失い、Host Git情報やOCIの共有は作業同士を結びつけます。

## 結果

新しい構成は新しい参照を開いて使い、元の作業は残ります。
明示した1〜8レポに対応します。linked worktree入力は別のclient import機能です。
Git push・通信の権限を増やさず、巨大レポの性能確認を意味しません。
