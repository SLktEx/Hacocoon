# 管理対象データの世代を排他的に採用する

状態: 採用、実装候補。[English](0087-atomic-managed-data-generations.md)

## 判断

現在世代の選択を、保存領域の準備完了・所有者・削除除外と同じ永続カタログのトランザクションで扱います。
取り込み側は、リセット時のランダムな識別子と互換条件を含む期待世代の全項目を渡します。
共通の領域作成処理で一式を準備・検証してから、照合と採用を排他的に行います。
古い世代は見送り、保存結果が不明なら領域を保持します。現在世代の領域は削除から保護します。

Coreは基盤に依存しない識別と寿命の契約を持ち、Standardはキャッシュ設定・互換性の意味・通常Envからの収集を持ちます。
Incusはcustom volumeとBtrfsコピーを担当します。Env由来のキャッシュをHostの信頼済みツールや設定にせず、
キャッシュ領域をOCIのHost制御経路へ渡しません。

リセットは識別子を変えて選択だけを外します。旧領域を削除したり、Envのローカルコピーを置換したりしません。
競合候補の片付けは、他の管理領域削除と同じ実体不在確認後の最終処理を使います。

## 不採用案

キャッシュ専用の索引・独立したロックでは、カタログ側の削除と競合し、削除済み領域を選択する恐れがあります。
番号だけの照合では、リセット後に古い取り込み側が一致してしまいます。
ファイル単位のマージは合意した世代一式の方針に反し、ツール固有の整合条件を仮定します。
採用時のすべてのエラーで候補を削除すると、保存結果が不明な場合に採用済み共通元まで消す恐れがあります。
独自のcleanupは所有記録を解放する判断を重複させます。OCIの接続経路を流用すると、
キャッシュへOCI固有の配置先とnesting設定を適用してしまいます。

これは[キャッシュ契約](../design/cache-generations.ja.md)の基盤です。
Host設定、指定パス収集、Envとともに削除する接続領域の実装が残っており、利用全体の完成を示しません。

## Host選択の判断

Standard設定の既定範囲は正確なWorkspace単位とし、共有には明示的なグループと
ツール・基盤・データ形式の互換条件を必要とします。パス指定と対象レポを含む規則全体を
区別可能な構造のdigestへ結び付けます。Base名、Envの検査結果、任意のclient項目から
互換性を推測しません。短縮された内部名でもカタログの完全なdigestとの一致を必要とします。
世代初期化の前に選択全体を固定・検証し、レポのメンバー識別には管理対象カタログを使います。
Env内パスからメンバーを推測しません。設定の読み取りだけで保存や有効化を許可しません。
共有判断をHostの信頼済み設定へ置き、Coreの世代管理契約を維持するための判断です。
[選択の契約](../design/cache-generations.ja.md#hostによる対象と互換条件の選択)を参照してください。
