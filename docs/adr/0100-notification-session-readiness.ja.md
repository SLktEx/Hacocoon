# ADR 0100: 通知セッションの準備完了

状態: 開発候補として採用。

## 背景

ユーザー・WSL配布ごとのmutexは、最初のWSL準備確認と終了時の所有対象cleanupを
含む通知処理全体を保護します。使用中のmutexだけではCOMの表示受付が存在するとは
判断できません。この間の起動要求は、所有権を取れない二つ目のサーバーをWindowsに
起動させる可能性があります。CIではCOM作成失敗を記録しています。この競合の修正は、
記録した全失敗の原因が同じだと証明するものではありません。

## 判断

mutexによる全期間の所有を維持し、表示の初期化完了は別の手動リセットWindows eventで
示します。所有権と準備完了を同時に待ち、両方が成立するときは所有権を優先します。
解放・放棄されたmutexを取得した時点で古い準備完了を消し、初期化後に公開します。
COM解除より前に公開を取り消し、cleanup完了までmutexを保持します。前の処理の待機と
自身の起動に別の上限を設け、通知元は両方を待てるようにします。mutexは同一OS threadで扱います。

このeventは受付可能性だけを示します。導入済み登録の検証、privateなcontroller接続、
一度限りのページnonce、最終要求の再照合、実際のShow応答を維持します。
eventの通知で操作を承認・成功扱いにせず、回答の自動再送も導入しません。

## 採用しない方法

COMの待ち時間だけを延ばしても、未公開の受付へ接続してしまいます。cleanup前の所有権解放は
前の履歴・peerのcleanupと新しい表示を競合させます。privateな準備確認前のCOM登録は、
要求を処理できない受付を公開します。承認の再送は操作の重複を招きます。
