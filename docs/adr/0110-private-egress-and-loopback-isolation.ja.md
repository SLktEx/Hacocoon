# ADR 0110: 私設ネットワークへの通信と Physical Host のループバック隔離

日本語 | [English](0110-private-egress-and-loopback-isolation.md)

状態: 採用。関連 Issue: #712。

## 決定

Standard HTTP／HTTPS プロキシは、既存のホスト名・Environment・プロトコル・
ポートに一致する許可を確認した後、私設 IPv4 と IPv6 ULA を含むグローバル
ユニキャストの DNS 応答を受け付けます。[ADR 0007](0007-controller-owned-standard-egress.md)
の公開アドレス限定という要件を置き換えます。Policy、承認、送信元の所有権、
CONNECT の SNI 検査の責任は変更しません。

プロキシは Physical Host のコントローラーと同じネットワーク名前空間で動きます。
ループバックへの接続は Environment の localhost ではなく Physical Host のサービスへ
届くため、ホスト名が承認済みでも拒否します。実行基盤と SSH の
`NO_PROXY=localhost,127.0.0.1,::1` は維持します。

IPv4 射影 IPv6 を IPv4 に戻したうえで、Go の `netip.Addr.IsGlobalUnicast` で
分類します。不正形式・ゾーン付きの応答と予約済み IPv4 `0.0.0.0/8`／`240.0.0.0/4`
も拒否します。非ユニキャスト、リンクローカル、ループバックは通常のユニキャスト
上流ではなく、リンクローカルにはインターフェースの指定とローカル基盤への到達という
問題もあります。私設・共有アドレスであること自体は拒否理由にしません。到達性は
Host の経路と実際の接続で決まり、公開・私設のどちらもアプリケーションの信頼を意味しません。

拒否対象が一つでもあれば応答全体を拒否します。接続前に許可対象の集合を固定し、
重複を除きます。失敗時も固定した集合だけを使い、再解決しません。次の接続には
新しい許可と名前解決が必要です。

HTTP／CONNECT の失敗境界で、選択した対象フィールドと固定の理由を一度だけ ERROR に
記録します。名前解決失敗、空の応答、ループバック・その他のアドレス拒否、接続失敗、
リクエスト失敗を区別し、キャンセル・期限超過を優先します。バックエンドの生のエラー、
URL、ヘッダー、本文はログに残しません。

## 不採用案と検証

公開アドレス限定は、私設ネットワークへの正当なホスト名認可を打ち消します。
全アドレスの許可は Physical Host のループバックやリンクローカルのサービスを公開します。
危険な応答だけを取り除くと、拒否対象を隠したまま、不適切な応答の一部で接続が成功してしまいます。
接続時の再解決は検査済みの集合を捨てます。NO_PROXY の拡大は通常のプロキシ経路を
迂回させるため不要です。

拒否と観測の契約は[外向き通信の設計](../design/egress-authorization.ja.md)が管理します。
回帰試験は RFC1918／ULA と許可対象の混在、射影アドレス、両順序の危険な混在応答、
固定した接続先、Policy 拒否、HTTP／CONNECT の診断、実行基盤・SSH の localhost 設定を
扱います。導入済み環境の私設ネットワークやゲストの localhost の実機受け入れは
証明しません。実際の経路、VPN、プロバイダーの挙動は別途確認します。
