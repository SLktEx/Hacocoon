# ADR 0027: 読み取った版に結び付けた Policy 編集

状態: 採用・実装済み。導入済み環境の設定往復は `2584ec6` で成功しました。[検証証拠](../status/acceptance-evidence.ja.md#development)を参照してください。

Policy の表示は正規化した JSON を使います。revision は元の実ファイルの正確なバイト列に結び付くため、空の任意配列が往復で表示上増減することを避けつつ競合を検出します。

通常の信頼された利用者が Physical Host の復旧シェルに入らず承認方針を確認・編集できるように、
`haco config` で既存 Policy の管理者ルールと saved_decisions を取得します。
`--edit` は利用者の editor、`--file` は同じスナップショット形式を使用します。

既存 management ソケットは管理者権限の境界です。設定の取得・置換はそこだけに登録し、
guest Git ソケットや表示専用の通知 bridge には公開しません。設定管理を実行対象
Capability や Environment の許可にしません。Core のプロバイダー、ブラウザーの必須依存、
管理ソケットの公開、認証情報の追加はありません。

revision はファイルの正確なバイト列を hash 化し、ファイルの不在も区別します。
承認保存と同じ非公開な advisory lock を保持して revision を比較します。
共通 writer が文書全体と容量を検証し、危険なファイルを拒否し、非公開一時ファイルへの
書き込み・同期・元内容の再確認・不可分なな置換を行います。協調する writer 同士の変更は
消しません。別の管理者 editor は同じ lock に従う必要があります。追加のバイト列比較は
lock を無視する任意のプロセスとの transaction を保証しません。

変更前の意図と永続化後の完了を監査します。操作 ID と新旧 revision だけを記録し、
設定内容は出しません。事前の監査失敗では置換せず、保存後の監査失敗では成功処理記録を
返さず recovery-required にします。現在の設定を確認してから再試行します。
競合した編集は保持し、自動 rebase・再試行しません。

却下した案: 承認と設定を別ファイルにする、後勝ちの import、暗黙のルール merge、
queue 受付を永続化の証明とする、縮小した通知 event に Policy 内容を載せる、
置換対象の Policy 自身に設定変更の承認を求める設計。
