# v0.13C — Optional OCI Plugin Image Deletion

Status: **first deletion slice implemented in the optional OCI plugin; physical immutable-Seed rebuild/GC remains part of the future Seed build pipeline.**

This document defines deletion semantics only for installations that explicitly enable the OCI plugin. Hacocoon Core does not own OCI workload-image deletion.

## CLI

```text
haco plugin oci image delete <reference[@sha256:...]> [--all-environments] [--json]
```

The plugin must be enabled first:

```text
HACO_PLUGIN_OCI=nerdctl
# or
HACO_PLUGIN_OCI=docker
```

The ordinary command records a trusted Seed-selection deletion tombstone. For the project-maintained nerdctl profile it also removes a matching reference from the dedicated Host Seed cache when that cache is configured. It does not rewrite existing Environments unless `--all-environments` is explicit.

## Default deletion

```text
HACO_PLUGIN_OCI=nerdctl haco plugin oci image delete docker.io/library/node:24
```

The plugin resolves `node:24` to one immutable digest from trusted plugin telemetry. If multiple digests have been observed for the mutable tag, deletion fails closed and requires an explicit `reference@sha256:...` target.

The operation then:

1. resolves and retains immutable `reference + digest` identity;
2. if the selected profile has a trusted Seed-cache backend, verifies the mutable reference still points to the resolved digest before removal;
3. records a plugin-owned deletion tombstone;
4. marks Seed rebuild as required so the future immutable Seed build omits the image.

Published Seed revisions remain immutable and are never edited in place.

## Driver behavior

Environment operations use the selected plugin driver:

```text
HACO_PLUGIN_OCI=nerdctl
  inventory -> nerdctl images ...
  delete    -> nerdctl rmi <reference>

HACO_PLUGIN_OCI=docker
  inventory -> docker images --digests ...
  delete    -> docker image rm <reference>
```

Neither path uses a force-removal option.

The Docker driver does **not** imply authority over an arbitrary Host Docker daemon. Therefore the first Docker-driver deletion slice records the tombstone and may remove matching Environment-local images, but reports the Host Seed cache as `not-configured` unless a future explicitly scoped Host-cache adapter is added.

The project-maintained nerdctl profile may use the dedicated Host namespace:

```text
hacocoon-seed
```

Only that explicit plugin profile uses Host-side `nerdctl --namespace hacocoon-seed ...` operations.

## All-Environment deletion

```text
haco plugin oci image delete docker.io/library/node:24 --all-environments
```

Before destructive Environment changes, the plugin preflights every managed Environment through Hacocoon's generic provider-neutral execution path.

For each Environment it lists image identities through the selected driver and requires an implicitly resolved mutable reference to still match the expected immutable digest. A moved tag is not deleted.

After preflight succeeds, the plugin removes the exact reference from each Environment using the selected driver's ordinary non-force image-removal command.

An image referenced by a running/stopped container may therefore fail removal rather than silently breaking that container. Per-Environment failures are reported. Partial deletion caused by a runtime race/failure returns recovery-required state and remains safe to retry because already-absent images are treated as no-ops.

## Manual Seed-selection override

Deleting an image is an explicit operator decision about **optional OCI Seed selection**, not a runtime/network denylist.

A deletion stores:

```yaml
reference: docker.io/library/node:24
digest: sha256:...
deleted_at: 2026-08-30T...
```

While that exact `reference + digest` tombstone exists, ordinary plugin telemetry may continue to observe the image in an Environment, but `haco plugin oci seed recommend` must not recommend or automatically promote it.

An Environment may still use its selected OCI profile to pull/run the image normally. Re-adding the exact identity to a future Seed requires an explicit future operator pin/override that deliberately clears or supersedes the tombstone; ordinary usage sampling never silently reverses manual deletion.

## Tag safety

The plugin does not blindly run an image-removal command from stale metadata.

For an implicit mutable reference such as `node:24`, deletion resolves and retains an immutable digest, then re-lists the relevant image store immediately before removal. The mutable reference is removed only when it still points to that digest.

If `node:24` was observed as digest A but now points to digest B, implicit deletion is refused.

Operators may explicitly target the old immutable identity:

```text
haco plugin oci image delete docker.io/library/node:24@sha256:<digest-A>
```

If the local tag has already moved to digest B, digest A is treated as absent from that local store and the current tag is not removed. The tombstone for A may still be persisted to exclude the old identity from future Seed selection.

## Security rules

- all OCI deletion code belongs to the optional plugin, not Core;
- deletion identity is `reference + immutable digest`;
- mutable-tag ambiguity fails closed;
- moved implicit tags are never deleted as if they still represented an older digest;
- explicit old-digest deletion never removes a newer image behind the same mutable tag;
- Host credentials are never copied into an Environment for deletion;
- Environment credentials are never harvested by deletion;
- `--all-environments` is explicit and never implied;
- force image removal is not used;
- the Docker driver never infers permission to operate a Host Docker daemon;
- published immutable Seed revisions are never mutated in place;
- a deletion tombstone overrides recommendation/top-10% auto-promotion until an explicit operator Seed override re-enables that exact identity;
- the tombstone does not prevent ordinary Environment runtime use;
- partial cross-Environment deletion is surfaced as recovery-required.

## Relationship to Seed build

```text
haco plugin oci image delete
       |
       +--> optional scoped Host Seed cache: remove reference
       |
       +--> plugin deletion tombstone
                  |
                  v
          next OCI Seed selection
                  |
             omit image
                  |
                  v
          publish new immutable Seed
```

Physical creation of the replacement immutable Seed remains part of the planned v0.13A plugin build/publish slice.

> **Image deletion is an OCI plugin feature. Core never requires nerdctl, Docker, or a Host OCI image cache merely to manage Hacocoon Environments.**
