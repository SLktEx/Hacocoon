# v0.13C — OCI Image Deletion

Status: **first deletion slice implemented; physical immutable-Seed rebuild/GC remains part of the Seed build pipeline.**

This document defines deletion semantics for OCI images managed or observed by Hacocoon.

## CLI

```text
haco image delete <reference[@sha256:...]> [--all-environments] [--json]
```

The ordinary command affects the trusted Host Seed cache and future Seed contents. It does not rewrite existing Environments.

`--all-environments` additionally attempts to remove the same immutable image identity from every currently managed Environment.

## Default deletion

```text
haco image delete docker.io/library/node:24
```

Hacocoon resolves `node:24` to one immutable digest from trusted usage telemetry. If multiple digests have been observed for the mutable tag, deletion fails closed and requires an explicit `reference@sha256:...` target.

The default operation then:

1. verifies the Host Seed-cache tag still points to the resolved digest;
2. removes the tag from the Hacocoon Host Seed namespace/cache with `nerdctl rmi` when present;
3. records a trusted deletion tombstone for `reference + digest`;
4. marks Seed rebuild as required so the next immutable Seed revision omits the image.

Published Seed revisions are immutable and are never edited in place. Old Seed revisions remain available while existing/recoverable Environments depend on them and may be garbage-collected only when normal Seed retention rules permit it.

## All-Environment deletion

```text
haco image delete docker.io/library/node:24 --all-environments
```

Before destructive Environment changes, Hacocoon preflights every managed Environment through the provider-neutral execution path.

For each Environment it lists the local nerdctl image identities and requires the mutable reference to still match the resolved immutable digest. A moved tag is not deleted.

After preflight succeeds, Hacocoon removes the exact reference from each Environment using ordinary `nerdctl rmi` and deliberately does **not** add `--force`.

Therefore an image referenced by a container may fail removal rather than silently breaking that container. Per-Environment failures are reported. If deletion becomes partial because of a runtime race/failure, Hacocoon returns recovery-required state and the operation is safe to retry: already-absent images are treated as no-ops.

## Stale telemetry protection

Deleting an image must not be immediately undone by old usage snapshots.

A deletion stores:

```yaml
reference: docker.io/library/node:24
digest: sha256:...
deleted_at: 2026-08-30T...
```

Recommendation ignores observations for that exact identity whose sample timestamp is at or before `deleted_at`.

This is intentionally not a permanent denylist. If an Environment genuinely acquires the same immutable image again and Hacocoon records a fresh sample after deletion, the image can become eligible for recommendation and top-10% automatic promotion again.

## Tag safety

Hacocoon does not blindly run `nerdctl rmi <tag>` from stale metadata.

Deletion resolves and retains an immutable digest, then re-lists the image store immediately before removal. The mutable reference is removed only when it still points to that digest.

If `node:24` was observed as digest A but now points to digest B, deletion of A through the mutable tag is refused. Operators may explicitly target an immutable identity with:

```text
haco image delete docker.io/library/node:24@sha256:<digest-A>
```

The digest remains the deletion identity even though nerdctl removal uses the validated local reference name for compatibility with local image-store behavior.

## Host Seed cache backend

The current first slice operates on the dedicated Host nerdctl namespace:

```text
hacocoon-seed
```

The CLI contract is intentionally independent of the physical cache backend. The planned Incus/Btrfs-backed trusted seed-cache instance may replace the storage implementation later so cache -> Seed Builder -> Seed can retain COW sharing without changing deletion semantics.

Deletion removes the image reference from the cache. Underlying containerd content may remain while another image/build-cache reference still retains the same blobs; Hacocoon does not run a broad forced prune as part of deleting one image.

## Security rules

- deletion identity is `reference + immutable digest`;
- mutable-tag ambiguity fails closed;
- Host credentials are never copied into an Environment for deletion;
- Environment credentials are never harvested by deletion;
- `--all-environments` is explicit and never implied by default deletion;
- `nerdctl rmi --force` is not used;
- published immutable Seed revisions are never mutated in place;
- stale telemetry cannot immediately auto-promote a just-deleted image;
- a later genuine post-deletion observation may make the image eligible again;
- partial cross-Environment deletion is surfaced as recovery-required rather than reported as complete.

## Relationship to Seed build

```text
haco image delete
       |
       +--> Host Seed cache: remove reference
       |
       +--> deletion tombstone
                  |
                  v
          next Seed selection
                  |
             omit image
                  |
                  v
          publish new immutable Seed
                  |
          move current-Seed pointer
```

The deletion command already persists the selection/tombstone state. Physical creation of the replacement immutable Seed is completed by the remaining v0.13 Seed build/publish slice.
