# Hacocoon v0.5 - Local GUI and IDE Specification

Status: Draft for implementation  
Requires: v0.4 External Capabilities acceptance gate

## 1. One-sentence definition

Hacocoon v0.5 lets Linux GUI applications, especially IntelliJ for Java development, run inside the same local Hacocoon Session as the agent/build tools while only the required display/device resources are projected to the host through explicit, revocable leases.

## 2. Position

Hacocoon does not build an IDE. The same `/workspace` is consumed by adapters:

```text
Session /workspace
   +-- shell/agent
   +-- VS Code over SSH
   +-- native Linux GUI process -> WSLg -> Windows desktop
```

Local Web/code-server is v0.6. Remote GUI is not required.

## 3. Goals

- `GUIProvider`/AccessProvider specialization;
- WSLg first provider;
- GUI process runs inside Session;
- IntelliJ validation profile;
- JDK/Gradle/Maven/index stay in Linux Session;
- `GUILease` records exactly which host resources are exposed;
- optional GPU/audio as separate capabilities;
- Git/AWS/Security behavior remains unchanged from shell/VS Code;
- unified local `haco open` UX without putting IDE semantics in Core.

## 4. Non-goals

- JetBrains proprietary Remote Development implementation;
- Hacocoon editor;
- paid remote-gateway dependency;
- remote/headless GUI guarantee;
- implicit broad WSLg mount;
- shared global IDE cache as Core feature.

## 5. Capability model

```yaml
principal: session:sess_123
action: session.gui.enable
resource: gui://local-wsl/wslg
conditions:
  gpu: false
  audio: false
```

The Security Framework owns authorization; the GUI provider only realizes an approved lease.

```text
GUILease
  id
  session_id
  provider
  resources
  gpu/audio flags
  created_at
  expires/revoked state
```

Cleanup is mandatory on disable/delete.

## 6. WSLg provider

Probe the actual host. Do not hardcode an assumed layout forever.

Possible resources include X11/Wayland/PulseAudio sockets/environment and optional vGPU device/library mapping. Attach only resources required by the selected mode.

```text
minimal display  = default
+audio           = explicit
+gpu             = explicit
```

Provider errors must explain which host capability is missing.

## 7. IntelliJ profile

```text
Windows desktop
    ^ GUI protocol
WSLg
    ^
Incus Session
    IntelliJ Linux process
    JDK
    Gradle/Maven
    /workspace
    agent
```

IntelliJ installation belongs to User Base/IDE profile. Hacocoon does not become a package manager.

Index/cache stays on Session/Linux storage. This avoids making Windows -> WSL filesystem traversal the normal Java indexing path.

## 8. UX

```bash
haco gui enable <session> [--gpu] [--audio]
haco gui disable <session>
haco gui run <session> -- <linux-gui-command...>
haco open <session> --ide intellij
haco open <session> --ide vscode
```

`--ide web` becomes available in v0.6.

## 9. Security requirements

- Session never receives arbitrary host display/device resources by default;
- GUI lease is Session-scoped;
- Session A cannot use Session B lease/socket mapping;
- GUI enable does not imply GitHub/AWS authorization;
- IntelliJ plugins are treated as Session-side untrusted code;
- GPU/audio expansion is visible in audit/doctor output;
- host HOME/credentials remain absent.

## 10. Implementation order

1. GUI host capability probe;
2. `GUIProvider` + fake contract tests;
3. GUILease integration with Security;
4. minimal WSLg display path;
5. generic `haco gui run`;
6. IntelliJ profile and Java repo validation;
7. `haco open` local router;
8. optional audio;
9. optional GPU;
10. cleanup/restart/negative tests.

## 11. Acceptance gate

- a generic Linux GUI smoke app runs in Session and displays on Windows;
- IntelliJ opens `/workspace` and Java indexing/build runs inside Session;
- Git/Security/AWS v0.3-v0.4 regression suites still pass from the GUI workflow;
- disabling/deleting Session removes GUI resources;
- Session A cannot reuse Session B GUI lease;
- optional GPU/audio are absent unless explicitly enabled;
- Core has no WSLg/IntelliJ implementation imports;
- v0.6 Web UI and v0.7 remote/EC2 are not required.
