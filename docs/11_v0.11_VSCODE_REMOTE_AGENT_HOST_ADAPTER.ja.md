# v0.11 VS Code Remote Agent Host Adapter

**状態:** 2026-08-29 に実装導入  
**互換性:** pre-1.0  
**実機Acceptance:** real Windows/WSL + Incus + VS Code Agents window Remote-SSH は未確認です。

## 目的

v0.11では、v0.10のSession→Environment bindingをVS CodeのAgents windowから実際に使いやすくします。

ただしHacocoon自身でAHPを再実装しません。

```text
Windows VS Code Agents window
          |
      Remote -> SSH
          |
 Hacocoon-managed SSH alias
          |
    localhost:<port>
          |
     Incus Environment
          |
      /workspace
          |
 VS Code CLI / Agent Host
  (VS Code側が起動)
```

HacocoonはEnvironmentと安全な接続準備を担当します。Agent Host、AHP、Agent UI、Remote Agent lifecycleはVS Code側の責務です。

## CLI

v0.11では次を追加します。

```text
haco-agent-host prepare
haco-agent-host release
```

Session用のremote slotを準備:

```bash
haco-agent-host prepare --session <opaque-id> /path/to/worktree
```

このcommandは:

1. Client側SSH private/public key pairを先に確認する。
2. v0.10のpersisted Session bindingをAcquireする。
3. 対象Environmentがrunningであることを確認する。
4. 既存Client Access経路でloopback-only SSHを用意する。
5. `~/.ssh/hacocoon/`配下へHacocoon管理SSH aliasを書く。
6. raw Session IDをaliasへ出さずhashからaliasを作る。
7. `--no-launch`がなければ`code --agents`でAgents windowを開く。
8. Agents windowの **New -> Remote -> SSH** で選ぶaliasを表示する。

終了:

```bash
haco-agent-host release --session <opaque-id>
```

Releaseはv0.10のpersisted binding proofを使い、任意Environment名を指定させません。

## なぜAHPを実装しないのか

現在のVS CodeはAgents windowからSSH remoteへ接続すると、VS Code側がremote CLI / Agent Hostを導入・起動してAHP通信を所有します。

そのためHacocoonは次をしません。

- AHP JSON-RPC/WebSocketの再実装
- Agent Host connection token管理
- VS Code内部process flagの固定API化
- AHP type/versionのCoreへの持ち込み
- Agents UIの再実装

変化する外部protocolをClient Adapter境界に閉じ込めます。

## 隔離の単位

v0.11で保証するのは:

> **1 prepared Hacocoon session slot = 1 v0.10 binding = 1 Environment**

です。

`--session`はtrusted callerが渡すopaque identityです。HacocoonがVS Code内部のtop-level Agent Session UUIDを自動で受け取るわけではありません。

したがって、同じSSH aliasへ接続してVS Code内で複数Agent Sessionを作れば、それらは同じEnvironmentを共有します。

「VS Code内部のhidden/sessionまで自動で1 Session 1 Incus」とは主張しません。

別々にwriteするAgentには別slot・別worktreeを使います。

```text
session-a -> worktree/a -> Environment A -> alias A
session-b -> worktree/b -> Environment B -> alias B
```

## Security Boundary

SSH private keyはClient側に残します。Environment側へ渡すのは既存SSH Access経路を通したpublic keyだけです。

```text
VS Code / Windows OpenSSH
          |
      127.0.0.1:<port>
          |
       Hacocoon
          |
       Incus:22
```

Coding Agentへ次を渡しません。

- Incus socket
- Hacocoon management state/control authority
- Client SSH private key
- Sandbox管理のための広いHost/Cloud credential

`prepare`途中でSSH設定に失敗してもSession Environment自体を勝手にReleaseしません。bindingを残して安全に再試行できます。

これは並列prepare時に、一方のClientがもう一方の取得したEnvironmentを誤削除するraceを避けるためです。

新しく作ったSSH forwardingだけはsetup failure時にcleanupします。

Environment削除は明示的な`release`だけが行います。

## Connection reuse

同じSessionで再度`prepare`した場合:

- alias / identity / port条件が一致するSSH接続は再利用する。
- identityや明示portが変われば新しい接続を作る。
- 新しい設定が有効になってから古いmanaged SSH connectionをrevokeする。
- 古い接続をrevokeできなければRecovery Requiredとして表に出す。

## Windows / WSL

Hacocoonがdedicated WSL、VS CodeがWindows Desktopにある場合、v0.8の`haco-vscode`と同様にWindows user profileを解決し、Windows側OpenSSHが読む`.ssh`設定へ書きます。

Dedicated Hacocoon WSL 2 + systemd要件もそのまま維持します。

## バージョンのつながり

```text
v0.8  haco-vscode       -> 普通のVS Code Remote-SSH
v0.9  Base contract     -> immutable Environment starting point設計
v0.10 Session Broker    -> Session ownership / dedicated Environment
v0.11 haco-agent-host   -> VS Code Agents window Remote-SSH adapter
```

v0.11はEnvironment ownershipを重複実装せず、v0.10を呼びます。

## Acceptance

Repositoryでは:

- `prepare/release`
- raw Session ID非露出
- private key非転送
- SSH connection reuse/rotation
- failure時に新規forwardだけcleanup
- bindingを暗黙Releaseしない
- v0.10 proof-based release
- Windows側SSH config解決
- release package/installへの`haco-agent-host`同梱
- build/vet/race/docs/workflow/release CI

を確認します。

Real machineでは2つのworktree/slot/Incusを作り、Agents windowからalias A/Bへ接続し、VS Code Agent HostがそれぞれのEnvironment内で動くことを別途確認します。

## 一文で言うと

> **v0.11は、v0.10の専用Environmentを標準Remote-SSHでVS Code Agents windowから使えるようにし、Agent Host/AHP自体はVS Codeへ任せるバージョンです。**
