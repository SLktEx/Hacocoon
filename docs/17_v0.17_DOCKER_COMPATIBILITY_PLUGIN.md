# v0.17 — Docker Compatibility Plugin

Status: **foundation implemented; complete plugin integration remains follow-up.**

v0.17 defines Docker compatibility as an optional plugin/integration feature. Hacocoon Core models Environments and execution; it does not require Docker Engine, containerd, or nerdctl.

## Maintained OCI profile

The project-maintained OCI plugin profile may use:

```text
containerd + nerdctl
```

That is a supported project profile, not a Core invariant. Docker compatibility is additive:

```text
maintained profile -> nerdctl -> containerd
compatibility      -> genuine Docker CLI -> optional/on-demand dockerd -> existing containerd where supported
```

The goal is to support tools that insist on Docker CLI/Engine APIs without forcing every Hacocoon installation to run a permanent daemon or even install OCI tooling.

## Plugin boundary

- Docker/nerdctl-specific orchestration belongs outside Core under `modules/plugin/oci` / `haco plugin oci`.
- `HACO_PLUGIN_OCI=nerdctl|docker` is explicit opt-in; unset means no OCI plugin.
- Genuine Docker CLI may be provided by the selected profile.
- `dockerd` must not become an always-on Hacocoon requirement.
- Engine startup is Environment-local and on-demand where supported.
- Never mount the Host Docker socket or grant Host control authority.
- Avoid unnecessary duplicate OCI content, without promising complete byte-level deduplication.

## Current repository reality

The repository contains the initial Docker compatibility design and plugin-owned systemd socket/service packaging foundation. This is **not yet a complete v0.17 feature**; full lifecycle/Base integration and supported-host acceptance remain follow-up work.

## Non-goals

- making containerd/nerdctl a Core requirement;
- making Docker Engine mandatory;
- running dockerd permanently when no workload needs it;
- exposing Host Docker/containerd sockets;
- placing Docker-specific concepts into Core.
