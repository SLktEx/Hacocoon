# v0.17 — Docker Compatibility Plugin

Status: **plugin boundary and driver composition implemented; Docker Engine/Base integration and real-host acceptance remain follow-up.**

v0.17 defines Docker compatibility as an optional plugin/integration feature. Hacocoon Core models Environments and execution; it does not require Docker Engine, containerd, or nerdctl as Core runtime dependencies.

## Project-maintained OCI profile

For users who opt into Hacocoon's project-maintained OCI workflow, the preferred profile is:

```text
containerd + nerdctl
```

That is a **profile choice**, not a Core invariant. A Base/Seed may provide another OCI stack or no OCI tooling at all.

Docker compatibility is additive for that profile:

```text
normal profile  -> nerdctl -> containerd
compatibility   -> genuine Docker CLI -> optional/on-demand dockerd -> existing containerd where supported
```

## Plugin boundary

OCI/container-specific implementation lives under `modules/plugin/oci` behind the plugin/adapter boundary and is explicitly composed with:

```text
HACO_PLUGIN_OCI=nerdctl
HACO_PLUGIN_OCI=docker
```

If the variable is unset, the OCI plugin is absent and Core must not probe for container tooling.

Current repository behavior includes:

- explicit nerdctl/Docker inventory-driver selection;
- OCI telemetry/recommendation/deletion state owned by `modules/plugin/oci`;
- Docker compatibility systemd units owned by `modules/plugin/oci/packaging/systemd`;
- no authority to an arbitrary Host Docker daemon merely because the Docker driver is selected.

## Docker Engine compatibility

The genuine Docker CLI may be installed for ecosystem compatibility. `dockerd` must not become an always-on Hacocoon requirement.

Where Engine compatibility is provided, the intended lifecycle is:

```text
Docker API client
      |
 /run/docker.sock
      |
socket activation
      v
    dockerd
      |
 existing Environment-local containerd where supported
```

Required rules:

- Engine startup is explicit/on-demand for workloads that need the Docker Engine API;
- the socket is Environment-local;
- the Host Docker socket is never mounted into an Environment;
- Docker compatibility does not grant Hacocoon/Incus Host control or reusable credentials;
- compatibility alone must not create a second Hacocoon-managed containerd/image store without demonstrated need.

## Current completion boundary

The plugin/package boundary, driver composition, and systemd packaging ownership are implemented. This is **not yet a complete** v0.17 feature: official Base/Seed bake-in, complete on-demand Engine lifecycle integration, and supported-host validation are still pending.

## Non-goals

- making OCI tooling mandatory for Hacocoon Core;
- making Docker Engine mandatory;
- running `dockerd` permanently when no workload needs it;
- exposing a Host Docker socket;
- placing Docker/containerd/nerdctl-specific concepts into Core.
