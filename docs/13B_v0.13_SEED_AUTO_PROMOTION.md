# v0.13B — OCI Plugin Seed Automatic Promotion Policy

Status: **selection policy implemented in the optional OCI plugin; Seed build consumption remains planned.**

This document refines the recommendation policy in `13A_v0.13_OCI_SEED_AND_COW.md`. The entire telemetry/recommendation/promotion flow described here belongs to the optional `modules/plugin/oci` integration. It is not a Hacocoon Core requirement.

## Default policy

When the OCI plugin is enabled, Hacocoon ranks recent Seed recommendations by observed Environment usage. Among recommendations that have an immutable OCI digest, the top **10%** are marked for automatic inclusion in the next Seed build.

The count is rounded up and has a minimum of one whenever at least one eligible recommendation exists:

```text
eligible recommendations   automatically promoted
1-10                       1
11-20                      2
21-30                      3
...
```

Formally:

```text
auto_count = ceil(eligible_count * 0.10)
```

with `auto_count >= 1` when `eligible_count > 0`.

The ranking remains deterministic:

1. number of recent Environments containing the exact image identity, descending;
2. most recent observation, descending;
3. image reference, ascending;
4. digest, ascending.

The current plugin telemetry window remains 30 days and opportunistic re-sampling considers snapshots fresher than 6 hours current.

## Immutable identity requirement

Automatic promotion applies only to recommendations with an observed immutable digest. A mutable tag without a digest is never automatically promoted.

The selected identity is therefore equivalent to:

```text
reference@sha256:...
```

A tag moving to a new digest is a different recommendation identity.

## CLI and machine-readable contract

`haco plugin oci seed recommend` marks automatically selected entries as `auto` in human-readable output.

The plugin must be explicitly enabled first, for example:

```text
HACO_PLUGIN_OCI=nerdctl haco plugin oci seed recommend
HACO_PLUGIN_OCI=docker  haco plugin oci seed recommend
```

JSON recommendations expose:

```json
{
  "reference": "docker.io/library/node:24",
  "digest": "sha256:...",
  "environments": 18,
  "percent": 90.0,
  "auto_promote": true
}
```

The planned OCI-plugin Seed Builder must consume `auto_promote=true` entries as part of the next Seed input set without requiring per-image manual approval. This does not mutate already-published Seeds or existing Environments.

If the OCI plugin is disabled, Core does not collect this telemetry and no automatic OCI Seed promotion occurs.

## Safety boundary

Automatic promotion chooses **image content**, not credentials or authority. Registry credentials, credential-helper output, workspace data, and arbitrary Environment files are never promoted into a Seed.

The plugin's Seed acquisition and build boundary remains:

```text
optional OCI plugin usage telemetry
      |
      v
rank + top 10% auto selection
      |
      v
trusted Host seed cache/acquisition
      |
      v
Offline Seed Builder
      |
      v
immutable Seed revision
```

A failed or partial Seed build must never become the current Seed merely because an image was automatically selected.
