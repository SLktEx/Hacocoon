# v0.13C — OCI Image 削除

Status: **削除の第1スライスは実装済み。immutable Seed の物理 rebuild / GC は残りの Seed build pipeline で実装する。**

この文書は Hacocoon が管理・観測する OCI image の削除 semantics を定義する。

## CLI

```text
haco image delete <reference[@sha256:...]> [--all-environments] [--json]
```

通常の削除は trusted Host の Seed cache と、以降に作る Seed の内容を対象にする。既存 Environment は書き換えない。

`--all-environments` を付けた場合だけ、現在管理中の全 Environment からも同じ immutable image identity を削除する。

## 通常削除

```text
haco image delete docker.io/library/node:24
```

`node:24` のような mutable tag は trusted usage telemetry から immutable digest 1つに resolve する。同じ tag について複数 digest が観測されている場合は fail closed し、`reference@sha256:...` を明示しない限り削除しない。

通常削除は以下を行う。

1. Host Seed cache 上の tag が、resolve 済み digest をまだ指しているか検証する。
2. 存在する場合は Hacocoon Host Seed namespace/cache から `nerdctl rmi` で削除する。
3. `reference + digest` の trusted deletion tombstone を保存する。
4. 次の immutable Seed revision からその image を除外するため Seed rebuild-required とする。

publish 済み Seed revision は immutable なので、その場で中身を書き換えない。old Seed revision は existing/recoverable Environment が依存している間は保持し、通常の Seed retention / GC 条件を満たしてから削除する。

## 全 Environment 削除

```text
haco image delete docker.io/library/node:24 --all-environments
```

Environment を破壊的に変更する前に、provider-neutral exec 経路で現在管理中の全 Environment を preflight する。

各 Environment で local nerdctl image identity を列挙し、暗黙に resolve した mutable reference が期待する immutable digest をまだ指していることを確認する。tag が別digestへ動いていた場合、そのtagは削除しない。

preflight成功後、各 Environment で通常の `nerdctl rmi` を実行する。**`--force` は付けない。**

したがって、running/stopped container がimageを参照していて通常削除できない場合は、その Environment の削除を失敗として表面化する。runtime race等で一部だけ削除済みになった場合は recovery-required を返す。再実行は安全で、既に image が無い Environment は no-op として扱う。

## 手動削除は Seed 自動選択への明示override

image削除は、古いtelemetryを一時的に無効化するだけではなく、operatorによる**Seed選択の明示判断**として扱う。

削除時には以下相当を保存する。

```yaml
reference: docker.io/library/node:24
digest: sha256:...
deleted_at: 2026-08-30T...
```

この exact `reference + digest` の tombstone が残っている間、Environment の利用統計に同じimageが再度現れても、`haco image seed recommend` は推薦も上位10% auto-promotionもしない。

これは runtime/network の denylist ではない。Environment は通常どおり `nerdctl pull` / `nerdctl run` してよく、private registry credentialを使った通常利用も妨げない。tombstoneが抑止するのは **Seedへの自動採用だけ**。

将来Seedへ戻したい場合は、Seed build policyでoperatorが明示pin/overrideする。その明示操作でtombstoneをclear/supersedeする。通常のusage samplingだけで手動削除を勝手に取り消してはいけない。

## Tag安全性

Hacocoon は stale metadata を見て雑に `nerdctl rmi <tag>` しない。

`node:24` のような暗黙mutable referenceでは、まず immutable digest を確定して保持し、削除直前に image store を再列挙する。mutable reference がその digest をまだ指している場合だけ reference名を削除する。

例えば telemetry 上で `node:24 = digest A` だった後、現在は `node:24 = digest B` になっているなら、暗黙の `node:24` 削除は拒否する。

古いimmutable identityを明示したい場合は以下を使う。

```text
haco image delete docker.io/library/node:24@sha256:<digest-A>
```

local の `node:24` が既に digest Bへ動いている場合、digest Aはそのlocal storeには存在しないものとして扱い、現在のtagを削除しない。一方でdigest Aのdeletion tombstoneは保存できるため、old identityをfuture Seed selectionから除外できる。

matching local referenceを実際に削除する場合は、local image storeとの互換性のため、検証済みreference名をnerdctlへ渡す。immutable digestはHacocoon側の削除identityとして保持する。

## Host Seed cache backend

第1スライスでは専用 Host nerdctl namespace を使う。

```text
hacocoon-seed
```

CLI契約は物理cache backendから独立させる。今後、Incus/Btrfs上のtrusted seed-cache instanceへ置き換えて、cache -> Seed Builder -> Seed 間のCOW block sharingを狙っても、削除semanticsは変えない。

1 imageの削除で広範囲な forced prune は行わない。別image/build cacheから同じblobが参照されている場合、containerd content自体が残ってもよい。

## セキュリティルール

- 削除 identity は `reference + immutable digest`。
- mutable tag のambiguityはfail closed。
- 暗黙mutable tagが別digestへ移動していたらold digest扱いで削除しない。
- explicit old digestを指定しても、同じtagのcurrent new digestを誤削除しない。
- Host credentialをEnvironmentへコピーしない。
- Environment credentialを削除処理で回収しない。
- `--all-environments` は明示指定時だけ有効。
- `nerdctl rmi --force` は使わない。
- publish済みimmutable Seedをin-place変更しない。
- deletion tombstoneはoperatorが明示overrideするまでrecommendation/上位10% auto-promotionより優先する。
- tombstoneはEnvironment内の通常runtime利用を禁止しない。
- cross-Environment削除がpartialになった場合はcomplete扱いせずrecovery-requiredを返す。

## Seed buildとの関係

```text
haco image delete
       |
       +--> Host Seed cache: reference削除
       |
       +--> deletion tombstone
                  |
                  v
          next Seed selection
                  |
              image除外
                  |
                  v
          new immutable Seed publish
                  |
          current-Seed pointer切替
```

削除commandはselection/tombstone stateまで保存する。replacement immutable Seedの実体作成は、残りのv0.13 Seed build/publish sliceが担当する。
