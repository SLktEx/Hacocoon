# v0.13C — Optional OCI Plugin Image Deletion

[English](13C_v0.13_OCI_IMAGE_DELETION.md) | **日本語**

Status: **image deletionのfirst sliceはoptional OCI plugin内で実装済み。immutable Seedのphysical rebuild/GCはfuture Seed build pipeline側。**

この文書はOCI pluginを明示的に有効化したinstallationだけに適用する。Hacocoon CoreはOCI workload image削除を所有しない。

## CLI

```text
haco plugin oci image delete <reference[@sha256:...]> [--all-environments] [--json]
```

pluginは先に明示的に有効化する。

```text
HACO_PLUGIN_OCI=nerdctl
# または
HACO_PLUGIN_OCI=docker
```

通常のdeleteはtrustedなSeed-selection tombstoneを記録する。project-maintained nerdctl profileでは、dedicated Host Seed cacheが設定されている場合だけmatching referenceも削除する。

`--all-environments`を指定しない限りexisting Environmentは書き換えない。

## Default deletion

```text
HACO_PLUGIN_OCI=nerdctl haco plugin oci image delete docker.io/library/node:24
```

pluginはtrusted telemetryから`node:24`を1つのimmutable digestへresolveする。mutable tagで複数digestを観測している場合はfail closedし、`reference@sha256:...`の明示指定を要求する。

処理は:

1. immutableな`reference + digest`をresolve/保持する
2. selected profileにtrusted Seed-cache backendがある場合だけ、削除前にmutable referenceがそのdigestを指していることを再確認する
3. plugin-owned deletion tombstoneを保存する
4. future immutable Seedから除外するためSeed rebuild requiredを記録する

published Seed revisionはimmutableのまま。in-place rewriteしない。

## Driverごとの挙動

Environment操作は選択されたplugin driverに従う。

```text
HACO_PLUGIN_OCI=nerdctl
  inventory -> nerdctl images ...
  delete    -> nerdctl rmi <reference>

HACO_PLUGIN_OCI=docker
  inventory -> docker images --digests ...
  delete    -> docker image rm <reference>
```

どちらもforce removalを使わない。

Docker driverを選んだからといって、arbitraryなHost Docker daemonを操作するauthorityが与えられるわけではない。

そのためfirst Docker-driver sliceではtombstoneとEnvironment-local削除は扱えるが、explicitにscopedされたHost-cache adapterが将来追加されるまではHost Seed cacheを`not-configured`として扱う。

project-maintained nerdctl profileではdedicated Host namespaceを使える。

```text
hacocoon-seed
```

Host側`nerdctl --namespace hacocoon-seed ...`を使うのはこのexplicit plugin profileだけ。

## All-Environment deletion

```text
haco plugin oci image delete docker.io/library/node:24 --all-environments
```

destructive action前に、pluginはgenericなprovider-neutral execution path経由で全managed Environmentをpreflightする。

各Environmentでselected driverからimage identityを再取得し、implicit mutable referenceがexpected immutable digestをまだ指していることを確認する。tagがmoveしていれば削除しない。

preflight成功後、selected driverのordinary non-force image removal commandでexact referenceを削除する。

containerから参照中のimageなどは削除失敗してよい。forceしてcontainerを壊すよりfailする。per-Environment failureは表示し、途中race/failureでpartialになった場合はrecovery-requiredを返す。already-absentはno-opなのでretry可能。

## Manual Seed-selection override

image deletionは **optional OCI Seed selectionに対する明示的operator decision** であってruntime/network denylistではない。

```yaml
reference: docker.io/library/node:24
digest: sha256:...
deleted_at: 2026-08-30T...
```

このexact `reference + digest` tombstoneがある間、plugin telemetryがEnvironmentで再観測しても`haco plugin oci seed recommend`はrecommend/auto-promoteしない。

Environmentはselected OCI profileでそのimageを普通にpull/runしてよい。

future Seedへ同じidentityを戻す場合は、tombstoneを明示的にclear/supersedeするoperator pin/overrideを将来のSeed-build policyで行う。ordinary samplingがmanual deletionを勝手に取り消してはいけない。

## Tag safety

pluginはstale metadataからblindにimage removalを実行しない。

`node:24`のようなimplicit mutable referenceはimmutable digestをresolve/保持し、remove直前にre-listする。現在も同じdigestを指している場合だけtagを削除する。

observed digest Aからdigest Bへmoveしていたらimplicit deletionは拒否する。

old identityを明示したい場合:

```text
haco plugin oci image delete docker.io/library/node:24@sha256:<digest-A>
```

local tagがdigest Bへ移っているならdigest Aはそのlocal storeに存在しないものとして扱い、current tagは削除しない。ただしAのtombstoneはfuture Seed selectionから除外するため保存できる。

## Security rule

- OCI deletion codeはすべてoptional pluginに置きCoreへ入れない
- deletion identityは`reference + immutable digest`
- mutable-tag ambiguityはfail closed
- moved implicit tagをold digestとして削除しない
- explicit old-digest deletionでnewer tagを消さない
- Host credentialをEnvironmentへ渡さない
- Environment credentialをharvestしない
- `--all-environments`はexplicit opt-in
- force image removalを使わない
- Docker driverからHost Docker daemon authorityを推測しない
- published immutable Seedをin-place mutateしない
- tombstoneはexplicit Seed overrideまでrecommendation/top-10% auto-promotionを抑止する
- tombstoneはordinary Environment runtime useを禁止しない
- partial cross-Environment deletionはrecovery-requiredとして表面化する

## Seed buildとの関係

```text
haco plugin oci image delete
       |
       +--> optional scoped Host Seed cache: remove reference
       |
       +--> plugin deletion tombstone
                  |
                  v
          next OCI Seed selection
                  |
             omit image
                  |
                  v
          publish new immutable Seed
```

replacement immutable Seedのphysical creationはplanned v0.13A plugin build/publish sliceの責務。

> **image deletionはOCI plugin機能。Hacocoon Environmentを管理するだけならCoreはnerdctl / Docker / Host OCI image cacheを要求しない。**
