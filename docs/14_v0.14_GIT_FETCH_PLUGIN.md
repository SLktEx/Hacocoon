# v0.14 — Git Fetch Plugin

Status: **implemented on `main`.**

v0.14 adds policy-scoped GitHub fetch to the existing Git/GitHub extension surface without turning ordinary Git into a Hacocoon Core responsibility.

```text
haco plugin git fetch <environment>
haco plugin git fetch <environment> --remote upstream
```

## Authority boundary

- The registered Workspace repository identity and GitHub remote are validated before privileged execution.
- Fetch uses a verified GitHub URL and fixed remote-tracking refspec rather than repository-controlled `remote.<name>.fetch`.
- Tags and submodules are not fetched implicitly.
- HTTPS GitHub authentication explicitly uses Host-owned `gh auth git-credential`.
- Credentials are not copied into the Environment, repository, capability request or audit log.
- SSH remotes may use Host keys/agent through the existing hardened broker path.

Fetch and push live under `haco plugin git`; local `git status`, `diff`, `commit`, worktree handling and ordinary developer Git UX remain Git's responsibility.

See [`GIT_GITHUB_CAPABILITY.md`](GIT_GITHUB_CAPABILITY.md) for the security contract.
