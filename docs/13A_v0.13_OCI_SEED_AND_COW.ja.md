# v0.13A — OCI Seed・利用統計・Btrfs/COW 最適化

Status: **利用統計 / recommendation の第1スライスは実装済み。Seed build / publish は引き続き計画中。**

この文書は Hacocoon の OCI Seed 方針を定義する。目的は、よく使う OCI image を immutable な Incus Seed に事前配置し、以降の Environment が Incus storage driver の通常の clone 経路を使うことで、Btrfs 上では未変更 block を COW 共有できるようにすることである。

Local Registry は **必須ではない**。Environment 内の通常の `nerdctl pull` は、operator が別途 registry/proxy を構成しない限り、通常どおり upstream registry へ直接アクセスする。

OCI/container image は Hacocoon/Incus の Base image と CLI 上でも明確に分離する。Base lifecycle は `haco base ...`、OCI/containerd/nerdctl 固有操作は optional な `haco plugin oci ...` namespace を使う。

## 目的

1. Environment 内の普通の `nerdctl` 体験を変えない。
2. 実際によく使われている OCI image を利用統計から把握する。
3. agent の利用だけで Base/Seed を勝手に肥大化させず、Seed 採用は operator-controlled にする。
4. Seed 用の network access は trusted Host 側に限定する。
5. Seed Builder は完全 offline、できれば NIC なしにする。
6. `containerd` を正常停止してから immutable Seed を publish する。
7. Environment 間で writable containerd state を共有せず、Incus/Btrfs の通常 COW clone だけを利用する。

```text
通常利用

Environment
    |
    | nerdctl pull
    v
Docker Hub / GHCR / private registry

Seed 作成

upstream OCI registry
        |
        | trusted Host only
        v
Hacocoon Host seed namespace/cache
        |
   OCI export / stream
        |
        v
Offline Seed Builder
(NICなし / registry接続なし)
        |
 containerd import/unpack
        |
 containerd clean stop
        |
        v
immutable Incus Seed revision
        |
      Incus clone
   (Btrfs COW when used)
      /    |    \
   Env A Env B Env C
```

## Environment 内の通常挙動

Seed membership は optimization であり OCI allowlist ではない。

Seed に image があればその Environment の local containerd state からそのまま利用できる。Seed に無ければ、Hacocoon の network policy が許す範囲で通常どおり upstream へ直接 pull する。

```text
nerdctl pull docker.io/library/python:3.14
nerdctl pull ghcr.io/example/tool:1.2
```

Seed のために image 名や `nerdctl` syntax を書き換えない。

private registry の認証は別の authority 問題として扱う。Host の credential を arbitrary Environment に自動コピーしてはいけない。Environment 自身の credential、標準 nerdctl/Docker credential helper、または将来の Hacocoon credential-broker plugin を使えるが、Local Registry を必須にはしない。

## 絶対に守る分離ルール

禁止:

```text
shared writable /var/lib/containerd
        +--------+--------+
        |        |        |
      Env A    Env B    Env C
```

採用:

```text
immutable Seed filesystem
        |
   Incus storage clone
        +--------+--------+
        |        |        |
 independent   independent
 containerd    containerd
 state A       state B
```

Env A の image 削除・追加・破損が Env B の論理 containerd state を変えてはならない。

## Host 側 Seed image 取得

何を Seed に入れるかを決めるのは coding agent や Seed Builder ではなく、trusted Host 側の Seed Manager とする。

Host は専用 containerd namespace を利用してよい。

```text
nerdctl --namespace hacocoon-seed pull <image>
```

これにより Hacocoon Seed 用 content/cache を unrelated host workload と分離できる。

権限境界は以下で固定する。

```text
Host seed acquisition     upstream Internet: policy により許可
Seed Builder              upstream Internet: 禁止
Coding Environment        通常 pull: 別途 network policy で管理
```

authenticated upstream の場合、Host は Host-owned credential / credential helper を使う。Seed に入るのは image content と immutable digest であり、registry credential ではない。

## Offline Seed Builder

Seed Builder は意図的に単純な offline helper にする。

1. logical Base を immutable Base revision に resolve する。
2. operator-approved Seed image list を確定する。
3. trusted Host 側で image を取得し immutable OCI digest を確定する。
4. Host から OCI archive/stream を temporary Seed Builder に渡す。
5. builder は pinned parent Base から作り、general network access を与えない。できれば NIC 自体を付けない。
6. OCI content は supported containerd/nerdctl import 経路から読み込む。
7. requested digest が全て存在し利用可能であることを検証する。
8. `containerd` を正常停止する。
9. builder instance を停止する。
10. immutable Incus image として publish する。
11. parent Base revision と exact OCI digest を Seed manifest に保存する。
12. publish/validation 成功後だけ current-Seed pointer を移動する。
13. temporary builder を削除し、cleanup を証明できなければ recovery-required を返す。

Builder は Docker Hub / GHCR / private registry / Hacocoon Registry のどれにも接続しない。必要な OCI content は trusted Host からのみ受け取る。

live な `/var/lib/containerd` を `cp` / `rsync` / tar / shared writable mount でコピーしてはいけない。

## Seed manifest

概念上は以下を保持する。

```yaml
base:
  name: haco/ubuntu-26.04
  revision: sha256:<immutable-incus-base-fingerprint>

seed:
  revision: sha256:<immutable-published-seed-fingerprint>

images:
  - requested: docker.io/library/node:24
    digest: sha256:<digest>
  - requested: docker.io/library/golang:1.26
    digest: sha256:<digest>
  - requested: ghcr.io/example/private-tool:1.2
    digest: sha256:<digest>
```

mutable tag は入力上の利便性にすぎない。Seed identity は immutable OCI digest と parent Base revision に基づく。

## 利用統計

Seed 選定は実利用に基づいて行うが、agent の pull 実績から自動で Base/Seed をその場で書き換えない。

第1スライスでは trusted Host に **Environment ごとの最新 OCI image snapshot** を保存する。provider-neutral な Environment exec 経路から通常の `nerdctl images` を取得し、Seed recommendation に必要な identity だけを記録する。

記録するもの:

- Environment ID
- sample 時刻
- repository
- tag（存在する場合）
- immutable digest（取得できる場合）

記録しないもの:

- shell/command history
- container output
- registry password/token
- credential-helper response
- workspace content

現在の CLI:

```text
haco plugin oci seed sample
haco plugin oci seed recommend
```

`sample` は known Environment 全件を強制 sample する。

`recommend` は stale snapshot を適宜 refresh した後に recommendation を計算する。初期 default は以下。

- 6時間以内の snapshot は fresh とみなし再 sample しない。
- recommendation は直近30日以内の snapshot を使う。

停止済み / unavailable Environment の sample は失敗してよい。他の有効な snapshot から recommendation は作り続け、失敗 Environment は明示的に表示する。

## Recommendation の意味

specific `reference + immutable digest` が何個の recent Environment snapshot に存在したかで集計する。

```text
docker.io/library/node:24@sha256:aaa...      18 envs   90.0%
docker.io/library/golang:1.26@sha256:bbb...  15 envs   75.0%
postgres:18@sha256:ccc...                    12 envs   60.0%
```

同じ Environment を何度 sample しても重みは増えない。store は Environment ごとの latest snapshot だけを recommendation weight に使う。

immutable digest を観測できない image は telemetry state に残ってもよいが、Seed recommendation には出さない。mutable tag だけを Seed identity として推薦してはいけない。

Recommendation 自体は publish 済み Seed を書き換えない。上位10%の自動選択は `13B_v0.13_SEED_AUTO_PROMOTION.ja.md`、手動削除 tombstone の優先規則は `13C_v0.13_OCI_IMAGE_DELETION.ja.md` が定義する。

## Seed 選択

logical Base は current Seed pointer を持ってよいが、Environment 作成時には v0.11 と同様に immutable Seed fingerprint に pin する。

Seed manifest の parent Base revision と、現在の logical Base が resolve する parent revision が一致するときだけ compatible とする。parent Base が動いた場合、old Seed を新 revision の starting point に暗黙利用しない。

existing Environment は作成時の exact revision に残る。

## Btrfs/COW

Hacocoon 自身が Incus 管理下の Btrfs subvolume を直接操作しない。Incus の標準 image -> instance clone 経路を利用する。

Btrfs pool では Seed 由来の未変更 block が COW 共有され、Environment 固有の write だけが分岐することを期待する。

Btrfs 固有 path/subvolume を Core API に持ち込まない。Btrfs は provider/storage optimization であり Core concept ではない。

non-COW backend でも Seed image 自体は利用できるが、同等の physical storage savings を保証してはいけない。

## Optional Local Registry

Local Registry/proxy は、Seed miss が多く upstream download が重複する環境や、centralized OCI policy point が必要な環境向けの将来 optional optimization とする。

以下には不要である。

- Environment の通常 `nerdctl pull`
- Host-side Seed acquisition
- offline Seed Builder
- usage telemetry
- Btrfs/COW Seed clone

採用する場合も adapter/infrastructure concern とし、Core dependency にしない。

## 容量表示

以下を区別する。

- Host seed-content/cache storage
- immutable Seed image storage
- Environment logical filesystem size
- backend が測定できる physical exclusive bytes
- backend が測定できる shared/COW bytes
- optional Registry storage

実測できない場合に `Environment数 × image size` をそのまま savings と主張しない。

## セキュリティ要件

- Environment 間で writable containerd root を共有しない。
- Host containerd/Docker socket を Seed Builder / coding Environment に渡さない。
- Incus/Hacocoon control socket を Seed Builder workload に渡さない。
- Seed Builder は arbitrary upstream network path を持たず、できれば NIC なし。
- networked Seed acquisition は trusted Host 側だけで行う。
- upstream credential は Host-owned のままにし Seed に埋め込まない。
- telemetry は OCI identity のみ記録し secrets / arbitrary process data / workspace content を記録しない。
- malformed image ref/digest/persisted telemetry は fail safely する。
- mutable tag だけを Seed identity にしない。
- publish 前に containerd を正常停止する。
- partial build を current Seed にしない。
- cleanup failure を recovery-required として表面化する。
- active/recoverable Environment が依存する Seed revision を GC しない。

## 実装スライス

### 実装済み — usage telemetry

1. Host-side latest-snapshot store。process serialization + atomic replacement。
2. known Environment の provider-neutral `nerdctl images` sampling。
3. opportunistic sampling の6時間 staleness guard。
4. 30日 recommendation window。
5. raw sample count ではなく per-Environment weighting。
6. recommendation は immutable digest 必須。
7. partial sample failure を明示。
8. `haco plugin oci seed sample|recommend` の human/JSON output。

### 計画中 — Seed build

1. explicit operator-approved Seed image list。
2. Host-side dedicated seed namespace/content cache。
3. public/authenticated upstream の Host-side pull + digest resolution。
4. OCI export/stream を offline Seed Builder へ注入。
5. publish 前の clean containerd shutdown。
6. immutable Incus Seed publish。
7. validation 成功後のみ current-Seed pointer を atomic move。
8. future Environment create 時の compatible Seed resolve。
9. normal Incus clone による Btrfs COW benefit。
10. fake-provider test と real Incus+Btrfs+containerd/nerdctl acceptance の分離。

## Acceptance

最終的に最低限以下を証明する。

1. telemetry が2つの独立 Environment を sample でき、credential/workspace content を取得しない。
2. 同じ Environment を繰り返し sample しても recommendation weight が増えない。
3. malformed/unknown digest を Seed recommendation にしない。
4. unavailable Environment を sample failure として出しつつ valid recent snapshot を利用できる。
5. Host-side acquisition が public/private image を取得でき、builder に credential を渡さない。
6. Seed Builder が arbitrary Internet に到達できない。
7. 1つの Seed から作った2 Environment の containerd logical state が独立している。
8. new Seed publish 後も existing Environment は old revision のまま。
9. parent Base revision change で old Seed が incompatible になる。
10. Btrfs pool では physical usage 実測で COW sharing を確認する。
11. non-COW backend で equivalent dedup を誤表示しない。

## Non-goals

- writable containerd DB/content root の Environment 間共有
- Seed construction のための Local Registry 必須化
- normal `nerdctl pull` の image-name rewrite
- Seed 更新時の existing Environment 書き換え
- arbitrary agent/developer Environment のそのまま Seed 化
- workspace / credential の Seed 混入
- Seed membership の allow/deny policy 化
- 観測した image 全件の自動 Seed 昇格
- Hacocoon Core から Incus/Btrfs internals を直接操作
- COW 非対応 backend への physical dedup 保証

> **Environment は普通の nerdctl pull を維持する。Hacocoon は trusted 側で利用統計を取り、よく使う immutable image identity を推薦し、approved Seed content は Host で取得して offline Seed Builder に渡す。容量削減は Incus/Btrfs COW に任せ、shared writable containerd trust boundary は作らない。**
