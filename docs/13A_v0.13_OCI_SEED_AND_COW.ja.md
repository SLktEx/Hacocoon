# v0.13A — Optional OCI Plugin Seed・利用統計・Btrfs/COW 最適化

Status: **optional OCI pluginの利用統計 / recommendation第1スライスは実装済み。Seed build / publishは引き続き計画中。**

この文書はOCI pluginのSeed方針を定義する。OCI Seedはcontainer toolingを使うinstallation向けのoptional optimizationであり、Hacocoon Coreの最低限contractではない。

Hacocoon CoreはOCI pluginを無効にし、`containerd` / `nerdctl` / Dockerが存在しない状態でも動かなければならない。

Local Registryも必須ではない。registry access、OCI image取得、image telemetry、Seed construction、container CLIの挙動はすべてoptional OCI plugin/profile側の責務とする。

## Plugin境界

OCI pluginは明示的に有効化する。

```text
HACO_PLUGIN_OCI=nerdctl
# または
HACO_PLUGIN_OCI=docker
```

未設定ならOCI telemetryをcompositionせず、container CLIを実行せず、Environment内のOCI runtimeも要求しない。

project-maintainedな`nerdctl` profileでは`containerd + nerdctl`を提供してよい。Docker profileでは本物のDocker CLIと、必要な場合だけplugin-ownedなDocker Engine compatibility unitを提供してよい。どちらもCore invariantではない。

## 目的

1. Hacocoon CoreをOCI/container toolingから独立させる。
2. 選択されたOCI plugin profileの通常挙動をEnvironment内で保つ。
3. telemetry有効時だけ、よく使われるOCI imageをSeed候補として把握する。
4. Seed選定をarbitrary agent authorityから分離する。
5. networked Seed acquisitionはtrusted Host側のOCI plugin componentだけで行う。
6. Seed Builderは完全offline、できればNICなしにする。
7. 選択されたOCI runtimeを正常停止してからimmutable Seedをpublishする。
8. storage/providerの通常clone semanticsを使い、Btrfsでは未変更blockをCOW共有する。

```text
optional OCI workload use

Environment
    |
    | selected plugin/profile CLI
    | 例: nerdctl pull / docker pull
    v
Docker Hub / GHCR / private registry

optional Seed construction

upstream OCI registry
        |
        | trusted Host-side OCI plugin only
        v
OCI plugin Seed cache/acquisition
        |
   OCI export / stream
        |
        v
Offline Seed Builder
(NICなし / registry credentialなし)
        |
 selected OCI import/unpack path
        |
 clean runtime stop
        |
        v
immutable Seed revision
        |
 Environment/storage clone
   (Btrfs COW when used)
      /    |    \
   Env A Env B Env C
```

## Environment内の通常挙動

Seed membershipはoptimizationでありOCI allowlistではない。

選択されたplugin profileが公開するtoolの通常command semanticsを維持する。project-maintained nerdctl profileなら例えば:

```text
nerdctl pull docker.io/library/python:3.14
nerdctl pull ghcr.io/example/tool:1.2
```

Docker CLI profileなら通常の`docker pull`を使う。

SeedのためにCoreがimage名やcontainer CLI syntaxを書き換えてはいけない。

private registry認証は別authorityとして扱う。Host credentialをarbitrary Environmentへ自動コピーしてはいけない。Environment-owned credential、標準credential helper、または将来のcredential-broker pluginを使えるが、Local Registryを必須にはしない。

## 絶対に守る分離ルール

OCI pluginの容量削減のために1つのwritable runtime rootをEnvironment間で共有してはいけない。

containerd profileでは次は禁止:

```text
shared writable /var/lib/containerd
        +--------+--------+
        |        |        |
      Env A    Env B    Env C
```

必要なmodel:

```text
immutable Seed filesystem
        |
 Environment/storage clone
        +--------+--------+
        |        |        |
 independent   independent
 runtime       runtime
 state A       state B
```

各Environmentは、他Environmentのlogical OCI runtime stateを変えずに独立して削除・破損・復旧・変更できなければならない。

## Host側 image acquisition

何をSeedへ入れるかを決めるcomponentはtrusted Host側のOCI pluginに置く。Hacocoon Core、Seed Builder、coding agentの責務にはしない。

nerdctl/containerd profileでは例えば専用Host namespaceを利用できる。

```text
nerdctl --namespace hacocoon-seed pull <image>
```

これはplugin profileの実装例でありCore APIではない。別driverでも次のauthority boundaryは維持する。

```text
OCI plugin Host acquisition   Internet/upstream: policyにより許可
Seed Builder                  Internet/upstream: 禁止
Coding Environment            selected profile behaviorとして別管理
```

authenticated upstreamではplugin Host componentがHost-owned credential/helperを使う。Seedに入れるのはimage contentとimmutable identityだけで、registry credentialを含めない。

## Offline Seed Builder

Seed Builderは単純なoffline helperにする。

1. logical Baseをimmutable Base revisionへresolveする。
2. explicitまたはpolicy-selectedなSeed image setを確定する。
3. trusted OCI-plugin Host側でimage取得とimmutable digest解決を行う。
4. OCI contentをHostからtemporary Seed Builderへexport/streamする。
5. builderはpinned parent Baseから作り、general network accessを与えない。できればNIC自体を付けない。
6. live runtime DBをコピーせずsupportedなplugin-profile import経路を使う。
7. requested digestが全て存在し利用可能であることを検証する。
8. selected OCI runtimeを正常停止する。
9. builder instanceを停止する。
10. Environment provider経由でimmutable Seed/Base revisionとしてpublishする。
11. exact parent Base revisionとOCI digestをSeed manifestへ保存する。
12. publish/validation成功後だけcurrent-Seed pointerを移動する。
13. temporary builderを削除し、cleanupを証明できなければrecovery-requiredを返す。

containerd profileではliveな`/var/lib/containerd`を`cp` / `rsync` / tar / shared writable mountでコピーしてはいけない。他runtimeのmutable DBにも同等ruleを適用する。

## Seed manifest

概念上は以下を保持する。

```yaml
base:
  name: haco/ubuntu-26.04
  revision: sha256:<immutable-base-fingerprint>

seed:
  revision: sha256:<immutable-seed-fingerprint>

images:
  - requested: docker.io/library/node:24
    digest: sha256:<digest>
  - requested: docker.io/library/golang:1.26
    digest: sha256:<digest>
```

mutable tagは入力上の利便性にすぎない。Seed identityはimmutable OCI digestとparent Base revisionに基づく。

## 利用統計

telemetryはoptional OCI pluginが完全に所有する。

第1スライスではtrusted Hostに **Environmentごとの最新OCI image snapshot** を保存する。transportにはgenericなEnvironment execを使うが、具体的なcontainer commandはplugin driverが選ぶ。

```text
HACO_PLUGIN_OCI=nerdctl
  -> nerdctl images --format ...

HACO_PLUGIN_OCI=docker
  -> docker images --digests --format ...
```

Core codeにどちらかのcommandを不変条件として埋め込んではいけない。

記録するもの:

- Environment ID
- sample時刻
- repository
- tag（存在する場合）
- immutable digest（取得できる場合）

記録しないもの:

- shell/command history
- container output
- registry password/token
- credential-helper response
- workspace content

現在のplugin CLI:

```text
haco plugin oci seed sample
haco plugin oci seed recommend
```

`sample`はknown Environment全件を強制sampleする。

`recommend`はstale snapshotを適宜refreshした後にrecommendationを計算する。初期defaultは:

- 6時間以内のsnapshotはfreshとみなし再sampleしない。
- recommendationは直近30日以内のsnapshotを使う。

停止済み / unavailable Environmentのsampleは失敗してよい。他のvalid snapshotからrecommendationを作り続け、failureは明示する。

OCI pluginが無効ならOCI telemetryは収集しない。

## Recommendation

specific `reference + immutable digest` が何個のrecent Environment snapshotに存在したかで集計する。

```text
docker.io/library/node:24@sha256:aaa...      18 envs   90.0%
docker.io/library/golang:1.26@sha256:bbb...  15 envs   75.0%
postgres:18@sha256:ccc...                    12 envs   60.0%
```

同じEnvironmentを何度sampleしてもweightは増えない。storeはEnvironmentごとのlatest snapshotだけを使う。

immutable digestを観測できないimageはplugin telemetry stateに残してもよいがSeed recommendationには出さない。

v0.13B plugin policyではeligible recommendationの上位10%を次回Seed inputへauto-promoteする。selectionはcredentialを付与せず、published Seedやexisting Environmentをその場で書き換えない。

## Seed選択

logical Baseはplugin-managedなcurrent Seed pointerを持ってよいが、Environment作成前にselected immutable Seed revisionへpinする。

Seed manifestのparent Base revisionと現在resolveされるparent Base revisionが一致する場合だけcompatibleとする。parent Baseが動いた場合、old Seedを新revisionへ暗黙利用しない。

existing Environmentは作成時のexact revisionに残る。

## Btrfs/COW

OCI pluginはEnvironment/storage providerの通常clone semanticsを使い、provider管理下のBtrfs subvolumeを直接操作しない。

Btrfs poolではpublished Seed由来の未変更blockをCOW共有し、write時だけ分岐できる。

Btrfs固有path/subvolumeをCore APIに持ち込まない。Btrfsはprovider/plugin optimizationでありCore conceptではない。

non-COW backendでもSeed image自体は利用できるが、同等のphysical storage savingsを保証してはいけない。

## Optional Local Registry

Local Registry/proxyは、repeated missのupstream download削減やcentralized OCI policy pointが必要なinstallation向けのoptional OCI plugin/infrastructure featureとする。

以下には必須ではない。

- selected OCI profileのdirect pull
- Host-side Seed acquisition
- offline Seed Builder
- usage telemetry
- Btrfs/COW Seed clone

採用してもCore dependencyにしない。

## セキュリティ要件

- OCI pluginはopt-in。Coreはpluginなしで動く。
- Environment間でwritable runtime rootを共有しない。
- Host containerd/Docker socketをSeed Builder / coding Environmentへ渡さない。
- Incus/Hacocoon control socketをplugin workloadへ渡さない。
- Seed Builderはarbitrary upstream network pathを持たず、できればNICなし。
- networked Seed acquisitionはtrusted plugin Host側だけで行う。
- upstream credentialはHost-ownedのままにしSeedへ埋め込まない。
- telemetryはOCI identityのみ記録しsecrets / workspace contentを記録しない。
- malformed image ref/digest/persisted telemetryはfail safelyする。
- mutable tagだけをSeed identityにしない。
- selected OCI runtimeをpublish前に正常停止する。
- partial buildをcurrent Seedにしない。
- cleanup failureをrecovery-requiredとして表面化する。
- active/recoverable Environmentが依存するSeed revisionをGCしない。

## 実装スライス

### 実装済み — optional OCI plugin usage telemetry

1. plugin-owned Host-side latest-snapshot store。process serialization + atomic replacement。
2. explicit `nerdctl` / Docker inventory driver。
3. generic Environment execはtransport boundaryとしてのみ利用。
4. opportunistic samplingの6時間staleness guard。
5. 30日recommendation window。
6. raw sample countではなくper-Environment weighting。
7. recommendationはimmutable digest必須。
8. partial sample failureを明示。
9. `haco plugin oci seed sample|recommend` のhuman/JSON output。
10. `HACO_PLUGIN_OCI`未設定時はpluginをcompositionしない。

### Planned second slice — Seed build / publish

completeなSeed build/publish E2Eは **まだ`main`に完全実装されていない**。planned second sliceは:

1. policy-selected Seed image list。
2. plugin Host-side Seed namespace/content cache。
3. Host-side authenticated/public upstream acquisition + digest resolution。
4. OCI export/streamをoffline Seed Builderへ注入。
5. publish前のclean selected-runtime shutdown。
6. immutable Seed publish。
7. validation成功後のみcurrent-Seed pointerをatomic move。
8. future Environment create時のcompatible Seed resolve。
9. normal provider cloneによるBtrfs COW benefit。
10. fake-provider testとreal Environment+Btrfs+OCI-profile acceptanceを分離。

## Acceptance

最終的に最低限以下を証明する。

1. OCI plugin disabledかつcontainer toolingなしでもCoreが初期化・動作する。
2. `HACO_PLUGIN_OCI=nerdctl`ではnerdctlだけでsampleする。
3. `HACO_PLUGIN_OCI=docker`ではDocker CLIだけでsampleする。
4. 同じEnvironmentを繰り返しsampleしてもrecommendation weightが増えない。
5. malformed digestをSeed recommendationにしない。
6. unavailable Environmentをsample failureとして出しつつvalid recent snapshotを利用できる。
7. Host-side acquisitionがauthenticated imageを取得してもbuilderへcredentialを渡さない。
8. Seed Builderがarbitrary Internetに到達できない。
9. 1つのSeedから作った2 Environmentのlogical runtime stateが独立する。
10. new Seed publish後もexisting Environmentはold revisionのまま。
11. parent Base revision changeでold Seedがincompatibleになる。
12. Btrfsではphysical usage実測でCOW sharingを確認する。
13. non-COW backendでequivalent dedupを誤表示しない。

## Non-goals

- OCI toolingをHacocoon Coreへ入れること
- writable OCI runtime DB/rootのEnvironment間共有
- Seed constructionのためのLocal Registry必須化
- normal plugin-profile pullのimage-name rewrite
- Seed更新時のexisting Environment書き換え
- arbitrary agent/developer EnvironmentのそのままSeed化
- workspace / credentialのSeed混入
- Seed membershipのOCI allow/deny policy化
- provider-owned Btrfs internalsをCoreから直接操作すること
- non-COW backendでphysical dedupを保証すること

> **OCI Seedはoptional plugin optimization。Hacocoon Coreはcontainer-tool-agnosticのまま、選択されたOCI plugin profileがnerdctl/Docker挙動、telemetry、Seed acquisition、runtime固有storage処理を所有する。**
