# v0.13A — OCI Seed & Btrfs/COW 最適化

Status: **v0.13 の第2スライスとして計画済み。`main` には未実装。**

この文書は [`13_v0.13_LOCAL_OCI_REGISTRY.md`](13_v0.13_LOCAL_OCI_REGISTRY.md) のストレージ最適化コンパニオンである。Local Registry / cache gateway は upstream からの重複ダウンロードを減らし、OCI Seed はよく使う展開済みコンテナイメージを各 Environment が独立コピーとして抱える量を減らす。

## 目的

選択した OCI image を一時的な trusted Seed Builder で `containerd` に事前取得し、`containerd` を正常停止した後、その root filesystem 全体を immutable な Incus Base/Seed image として publish する。以降の Environment は Incus の通常の storage clone 経路からその Seed を使う。

Incus storage pool が Btrfs の場合、未変更ブロックは COW によって物理共有されることを期待する。

**複数 Environment から同じ writable `/var/lib/containerd` を共有マウントしてはいけない。** 各 Environment の containerd state は論理的に完全独立でなければならない。

```text
Docker Hub / GHCR / allowed upstream
              |
              v
     Hacocoon Local Registry
              |
              v
        OCI Seed Builder
       containerd + nerdctl
              |
      containerd clean stop
              |
      builder instance stop
              |
       immutable publish
              v
       OCI Seed revision
              |
       Incus storage clone
        /      |      \
     Env A   Env B   Env C
```

## 2段キャッシュ

```text
Environment
    |
    | seed hit
    v
OCI Seed / COW             L1: 起動・物理容量最適化
    |
    | miss
    v
Hacocoon Local Registry   L2: OCI blob / 通信キャッシュ
    |
    | miss
    v
allowed upstream registry
```

- Local Registry は同じ OCI blob を Environment ごとに Internet から取り直すのを防ぐ。
- OCI Seed は、よく使う image の containerd content/snapshot が新規 Environment ごとに完全独立な物理コピーになるのを、COW backend 上で抑える。

Registry hit だけでは Environment 内の展開済み layer の物理重複排除は保証できない。Seed hit だけでは Seed に無い image の取得経路は解決しない。そのため両方を組み合わせる。

## 絶対に守る分離ルール

禁止:

```text
shared writable /var/lib/containerd
        +--------+--------+
        |        |        |
      Env A    Env B    Env C
```

採用:

```text
immutable Seed filesystem
        |
   Incus storage clone
        +--------+--------+
        |        |        |
 independent   independent
 containerd    containerd
 state A       state B
```

Env A の image 削除・破損・追加が Env B の論理状態を変えてはならない。

## Seed Builder のライフサイクル

Seed Builder は coding agent 用 Environment ではなく trusted Hacocoon build helper とする。

1. logical Base を immutable Base revision に resolve する。
2. その pinned revision から temporary Incus build instance を作る。
3. builder には Hacocoon Local Registry への必要最小限の到達性だけを与える。
4. managed `containerd` / `nerdctl` を検証する。
5. operator 指定の Seed image を通常の image reference で pull する。
6. 各 image の immutable OCI digest を記録する。
7. 必要な image が利用可能 / unpack 済みであることを検証する。
8. `containerd` を正常停止する。
9. builder instance を停止する。
10. immutable Incus image として publish する。
11. parent Base revision と OCI digest 一覧を Seed manifest に記録する。
12. temporary builder を削除する。cleanup を証明できない場合は recovery-required として表面化する。

live な containerd metadata DB を `cp` / `rsync` / tar / shared mount で複製してはならない。

## ネットワーク境界

現在の `haco-sandbox` は unmatched egress を fail-closed で拒否する。Seed Builder の都合で unrestricted Internet を許可してはならない。

```text
Seed Builder
     |
     | registry-only path
     v
Hacocoon Local Registry
     |
     v
trusted upstream fetch
```

したがって v0.13 の実装順序は以下とする。

1. Local Registry / cache gateway
2. Environment 側 transparent registry routing
3. Seed Builder 専用の狭い registry 到達経路
4. OCI Seed build / publish
5. 新規 Environment 作成時の compatible Seed 自動選択

Registry 経路が壊れている場合、Seed build は明示的に失敗する。Docker Hub / GHCR への直接 fallback や unrestricted egress は行わない。

## Seed manifest

概念上、少なくとも以下を保持する。

```yaml
base:
  name: haco/ubuntu-26.04
  revision: sha256:<immutable-incus-base-fingerprint>

seed:
  revision: sha256:<immutable-published-seed-fingerprint>

images:
  - requested: docker.io/library/node:24
    digest: sha256:<digest>
  - requested: docker.io/library/golang:1.26
    digest: sha256:<digest>
  - requested: docker.io/library/postgres:18
    digest: sha256:<digest>
```

`node:24` のような mutable tag は入力上の利便性にすぎない。Seed identity は parent Base revision と immutable OCI digest に基づく。

## Seed 選択

logical Base は current Seed pointer を持ってよいが、Environment 作成時には v0.11 と同様に immutable Seed fingerprint へ pin してから利用する。

また Seed が記録している parent Base revision と、現在の logical Base が resolve する parent revision が一致する場合だけ compatible とする。

Base A から作った Seed を、Base が B に更新された後も無条件で使い続けてはいけない。B 用 Seed が再構築されるまでは old Seed を compatible 扱いしない。

既存 Environment は作成時の exact revision のまま残る。

## Btrfs/COW

Hacocoon 自身が Incus 管理下の Btrfs subvolume を直接操作しない。Incus の標準 image -> instance clone 経路を利用する。

Btrfs pool では Seed 由来の未変更 block が COW 共有されることを期待する。変更部分だけ Environment 固有 block になる。

```text
shared Seed blocks
      +----------------+
      |                |
   Env A            Env B
   + A writes        + B writes
```

Btrfs 固有の path/subvolume は Core API に持ち込まない。Btrfs は provider/storage optimization であり Core concept ではない。

non-COW backend でも Seed image 自体は利用できるが、同等の物理容量削減を保証・表示してはならない。

## Seed に無い image

Seed membership は allowlist ではない。

```text
Seed: node / golang / postgres
Agent: nerdctl pull python:3.14
```

この場合は通常通り Local Registry へ行く。

```text
Env containerd
      |
   seed miss
      v
Hacocoon Local Registry
      |
 cache hit/miss
      v
allowed upstream
```

その追加 image はその Environment の独立 state に保存される。別の既存 Environment に自動反映しない。

## Seed 更新ポリシー

初期実装では operator が Seed image 一覧を明示指定する。agent の利用実績だけで勝手に Base/Seed を肥大化させない。

将来は Registry/pull 統計から候補を提案してよい。

```text
node:24       84% of recent Environments
python:3.14   72%
postgres:18   61%
rare/tool      2%
```

ただし recommendation と Seed mutation は別物とし、自動昇格は別ポリシーにする。

## 容量表示

以下を混同しない。

- Registry blob storage
- immutable Seed image storage
- Environment の logical filesystem size
- backend が測定可能な physical exclusive bytes
- backend が測定可能な shared/COW bytes

実測で証明できない限り「image size × Environment 数だけ削減できた」とは表示しない。

## セキュリティ要件

- writable containerd root を Environment 間共有しない。
- host の containerd/Docker socket を builder/agent Environment に渡さない。
- Incus/Hacocoon control socket を Seed workload に渡さない。
- builder upstream access は Local Registry 経由に限定する。
- upstream credential は trusted registry 側に残す。
- image ref / digest / alias / fingerprint / generated name を再利用前に検証する。
- mutable tag だけを Seed identity にしない。
- publish 前に containerd を正常停止する。
- partial build を current Seed pointer にしない。
- cleanup failure を recovery-required として報告する。
- active/recoverable Environment が依存する Seed revision を GC しない。

## 初期実装スライス

1. provider-owned Seed manifest と厳格な validation
2. Local Registry 経路完成後にのみ動く Incus Seed Builder
3. explicit seed image list
4. 全 Seed image の digest capture
5. publish 前の clean containerd shutdown
6. immutable Incus Seed publish
7. 成功・検証後だけ logical current-Seed pointer を atomic に移動
8. future Environment create 時の compatible Seed resolve
9. Incus pool が Btrfs の場合の自動 COW 利用（Hacocoon から隠し subvolume を直接触らない）
10. fake-Incus test と real Incus+Btrfs+containerd/nerdctl acceptance の分離

## Acceptance

real-host では最低限以下を証明する。

1. Docker Hub public image を Local Registry 経由で Seed S1 に入れる。
2. S1 から別々の Environment を2つ作る。
3. 両方で preseed image を upstream pull 無しに利用できる。
4. Env A の image state 変更が Env B に影響しない。
5. non-seeded image は通常通り Local Registry を経由する。
6. tag の digest が変わった Seed rebuild は新 immutable revision になる。
7. existing Environment は old revision のまま残る。
8. parent Base revision が変わると old Seed は incompatible になる。
9. Btrfs pool では物理使用量の実測で COW sharing を確認する。
10. non-COW backend では同等の dedup を誤表示しない。
11. Seed Builder が registry-only 想定時に arbitrary Internet へ到達できない。

## Non-goals

- 1つの writable containerd DB/content root の Environment 間共有
- Seed 更新時の existing Environment 書き換え
- 任意の agent/developer Environment をそのまま Seed 化
- workspace / credential の Seed 混入
- Seed membership の allow/deny policy 化
- cache hit 全件の自動 Seed 昇格
- Hacocoon Core から Incus 管理下 Btrfs internals を直接操作
- COW 非対応 backend への dedup 保証

> **Local Registry は共有 download cache、OCI Seed は immutable な preloaded runtime state。Incus/Btrfs の COW を使って物理容量を減らすが、Environment 間に shared writable containerd trust boundary は作らない。**
