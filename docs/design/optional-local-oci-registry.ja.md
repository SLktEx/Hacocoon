# 任意のローカル OCI レジストリ

状態: **延期した任意の基盤機能**。マイルストーンは予約せず、通常のイメージ取得や Seed 構築の必須条件にしません。

Hacocoon は全 Environment の `nerdctl pull` を専用レジストリへ強制中継しません。通常は設定した上流から取得し、必要に応じて信頼された Host のキャッシュや旧 Seed 取得を使います。

## 既定の動作

```text
Environment -> nerdctl pull -> 設定した上流レジストリ
```

Docker Hub、GHCR、非公開レジストリへの到達可否はネットワーク Policy に従います。

## 認証情報の境界

Host の認証情報を Environment へ暗黙にコピーしません。Environment 自身の認証情報には通常の nerdctl／Docker 互換設定を利用できます。対象と期限を限定する認証仲介はローカルレジストリなしでも成立します。旧 Seed 取得は Environment の認証情報と分離し、信頼された Host 側で認証します。

## 導入を検討する条件

実測や運用方針で必要性が分かった場合に限り、将来の任意機能として検討します。

- 多くの Environment が同じ Seed 未収録イメージを繰り返し取得する。
- 上流の回数制限や帯域が問題になる。
- OCI の Policy・監査を一か所に集約する必要がある。
- インターネット接続を制限し、内部の配布先だけを許可したい。

独立した機能として実装するときに、通常の規則で次のチェックポイントを決めます。

## 将来実装する場合の条件

OCI Distribution 互換実装を優先し、既定で公開しません。中継に使う再利用可能な上流認証情報は信頼する側に残します。中継必須の設定でレジストリが失敗しても、無制限の直接接続へ切り替えません。

共有名への自由な push を既定で許可せず、不変の識別にはダイジェストを使い、GC は保守的に行います。旧 Seed Builder はネットワークを持たず Host から内容を受け取るため、ローカルレジストリに依存しません。
