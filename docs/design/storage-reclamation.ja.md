# ストレージ容量回収

[English](storage-reclamation.md) | 日本語

状態: **実装済み。Windows/WSLの実機CIで確認済み**。
データや容量そのものを削減せず、未使用の割り当てを回収します。
既存のローカル導入環境と、中断したworkerの復旧確認は別です。

現在の操作記録がない場合、`haco reclaim --status`は保存された結果がないことを示して成功します。読み取りだけで、操作やレジストリキーは作成しません。過去に容量回収が実行されなかった、または完了したという証明にはなりません。`--review`にも確認対象はありません。不正な記録、アクセス失敗、明示した操作IDの欠落はエラーのままとし、処理中・失敗の証拠を「記録なし」に置き換えません。


## 起動と結果確認

管理対象の信頼されたHostで作業を保存し、実行します。

```bash
haco reclaim
```

停止・再起動を確認すると、インストール済みのWindows helperが一つのworkerを起動します。
`--yes` は確認の質問だけを省略します。終了コード0は**起動受付**であり、回収完了ではありません。
実行中の接続は切断されます。再起動後にHostへ入り、結果を確認します。

```bash
haco reclaim --status
```

GUID・パス・プールを指定する必要はありません。コントローラーの導入先を調べますが、
その情報だけでディスク操作を許可しません。登録がない、不正、変更済みなら拒否します。
応答が失われても処理が動いている可能性があります。再試行前に状態を確認してください。
未完了は完了不明、failedは非ゼロ終了と証拠保持です。状態確認は起動・再実行・記録削除を行いません。

古い導入環境には、通常のインストーラーで現在の本体と常設helperを適用する必要があります。
Linuxだけを対象にした公開回収コマンドはありません。

## hacoから失敗を再確認する

保存された結果を確認した後、明示的に実行します。

```bash
haco reclaim --review
```

失敗した操作を固定して確認を求めます。`--yes` は質問だけを省略します。
処理中のworker、対象操作の変更、不正な証拠があれば拒否します。
識別子確認のため登録済みWSLを開く場合がありますが、discard・圧縮・次の起動は行いません。
再確認に成功した後も、新しい試行には別途 `haco reclaim` が必要です。

終了済みの失敗は `ReviewedFailed-<operation GUID>` に元のバイト列を保存し、
永続化と再読み取りを確認してから置き換えを許可します。元の失敗はIDで引き続き参照できます。
中断の再確認は未完了の元データを保存した上で、現在の引き渡しを `interrupted` にします。
遅れて来たworkerは実行・結果公開できません。保存を証明できなければ置き換えを拒否します。
completeまたは確認済みinterruptedには新たな変更は不要です。
再試行のため記録を消さないでください。実際の登録済みworkerの中断・再確認は未確認です。

## 必要な結果

対象は設定済みIncus Btrfs プール、loop backing ファイル、外側のWSL ext4、登録済みWindows VHDXです。
ファイルシステムの容量・使用量、loopファイルの長さ・割り当て、
カーネルのdiscard量、Windowsの割り当てを別々に報告します。
観測がない値は不明のままで、回収量0も正当です。
trim量からWindowsの空き容量を推定しません。容量変化、不正な値、桁あふれ、種類の変化があれば成功にしません。

Workspace・Git・OCI・ボリューム・保存スナップショットは保持します。空きextentはファイルシステムの参照で判断します。
backing ファイルの切り詰め、プール容量の縮小、未使用オブジェクトの推測削除をしません。
隠れたバックアップやデータ移行も行いません。[明示的なデータ削除](../guides/data-lifetime.ja.md)は別操作です。

## 所有権とLinux側の処理

プールの作成・マウント・寿命はIncusが所有します。
アダプターは設定済みの作成済みBtrfs プールと `/var/lib/incus/disks/<pool>.img`、
設定されたマウント方針だけを対象にします。独自のIncusデータ配置は未対応です。
停止中のプールは通常のIncus利用でマウントし、別の管理者を作りません。

Linux側はbacking ファイル・マウント・loopの参照を固定します。
symlinkを含むパスとhardlinkを拒否し、単一デバイスのBtrfs、
device/inodeが一致するファイル全体への唯一のloop接続、offsetとsize 上限が0であることを確認します。
操作前後で名前と実体の対応を再確認します。Linux amd64/arm64では
必要な `openat2` 保証が必須で、弱い代替経路はありません。
doctorの観測だけを変更操作の前提にしません。

二つのdiscard処理は先に同期します。外側のext4 FITRIMは固定したbacking ファイルの
ファイルシステムを使い、プール権限に加えて導入済みWSLとの対応が必要です。他の外側FSは未対応です。
カーネル処理中の中断は試行・結果の証拠を保持し、未実行と判断しません。
プールを使用中に保ったIncusリソースを解放する前に参照を閉じます。

管理専用 `storage.reclaim-linux` RPCは正規の登録・導入IDだけを受け取り、
プール・パス・loop・コマンドを受け取りません。root所有の導入情報を照合し、
Btrfsをtrim、導入情報を再確認、ext4をtrimの順に行います。
5分の要求上限と同時実行の排除があります。失敗後の処理は省略し、
片付け失敗も別に残します。型付き失敗報告に生のサブプロセス出力は含めません。
通信の喪失は再実行の許可になりません。

## Windowsの登録とファイル識別

通常インストールはWSL 2の正確なGUIDとランダムな導入IDを、
root所有の `/etc/hacocoon/windows-registration.json` に記録します。
参照による走査、非公開で既存名を上書きしない原子的公開、
同じGUIDでの直列化した再試行により元のIDを保持します。
変更・不正な情報は拒否し、旧形式のディストリビューション名ファイルは変更しません。

Windowsの登録は、登録値、Linux導入ID、WindowsユーザーSID、固定したVHDXの実体を関連付けます。
現在のユーザーの `Software\Hacocoon\Reclamation\<registration GUID>` レジストリに
操作記録とは別に保持します。インストーラーの明示登録は同じ対応だけを再利用し、
異なる対応や操作履歴を上書きしません。Linux側の記録をコピーしただけでは権限を得られません。

通常インストールは同梱helperを検証し、
`%LOCALAPPDATA%/Hacocoon/reclamation/<区切り文字なし登録UUID>/haco-wsl.exe` に常設します。
所有ファイルで導入先を識別し、排他的な一時ファイル、checksum、flush、原子的置換を使います。
実行中workerが固定したバイナリは置換できません。所有不明・転送先変更・競合は拒否し、
自身の部分導入だけを再試行できます。PATH変更・昇格・展開済みZIPの保持は不要です。

Windows側はVHDXと親ディレクトリを固定し、reparse point・hardlinkを拒否してrenameを防ぎます。
ローカルdrive パスだけに対応し、UNC・デバイスパス・alternate ストリーム・曖昧なWin32表記は拒否します。
実参照で測る割り当てとファイル長は仮想ディスク容量とは別です。
動的で接続解除済みのVHDXを固定したvolume-GUID パスから開き、親ディスクはたどりません。
圧縮中も参照を保持します。open失敗を避けるために固定を外さないでください。

OpenVirtualDiskの共有違反は90秒まで待機し、他のエラーは直ちに失敗します。
圧縮自体は再試行しません。同期的なnative呼び出し一回が待機上限を超える場合はあります。
処理後に容量と仮想ディスク識別子を再確認します。

## 永続的なworkerの処理順

ユーザーSIDと登録GUIDで識別する保護されたglobal Windows objectにより、
Hacocoonの同時処理を排除します。既存objectや作成エラーなら待機・引き継ぎせず拒否します。
Windows所有者の直接WSL操作を防ぐ機構ではありません。先にobjectを作って妨害しても権限は得られません。

準備は排他と参照を保持して登録・導入情報を確認し、上限付きの正規なintentをflushしてから起動します。
workerは同じ操作・所有者・登録・diskを取り直して再確認します。
version 2はLinux開始と検証済み報告を停止前に記録します。
version 1のdisk-onlyの意味と元のバイト列は保持します。開始済み未完了は再実行しません。

固定された `haco _reclaim-linux` には関連付けたIDだけを渡します。
環境変数を消去した子プロセスは6分、型付き出力は4 KiBまでです。
Linuxの失敗・欠落・結果不明ではWindows側の停止へ進みません。worker全体は10分の上限です。

起動側は自身の実行ファイルを固定し、そのworker モードだけをJob breakaway、
consoleなし、NUL入出力、OS指定の作業ディレクトリ、消去した環境変数で起動します。
検証後・停止前に `RDY\n` とEOFだけを返すことが準備完了の条件です。
待機は3分までで、中断はpipeだけを閉じ、workerを終了・再試行しません。
外側のWindows Jobによりworkerが終了する可能性は残るため、未完了の証拠が必要です。

停止はSystem32のWSLに `--distribution-id <GUID>` で、
固定の `systemctl --no-block poweroff` を渡します。
全WSL停止、登録解除、名前への代替は行いません。
ディストリビューション停止だけでは共有WSL VMがdiskを解放したと判断できません。
他のディストリビューションの停止やglobal idle設定の変更で強制しないでください。
停止を試みた後は失敗時にも同じGUIDへの期限付き再開を試みます。
`/usr/bin/true` の再開だけではコントローラーの準備完了になりません。

最終結果には各段階を残します。API成功・PID・起動受付・WSL再開は、計測を伴う回収完了の代替ではありません。
古いhelperはversion 2やinterruptedを拒否し、項目を黙って捨てません。

## 実装の責任範囲

| 実装 | 責任 |
|---|---|
| `modules/runtime/incus` | プール選択、実体固定、FITRIM、計測 |

## 現在の実機確認

`5100d86` の[Windows通常利用ジョブ](https://github.com/SLktEx/Hacocoon/actions/runs/34623036552/job/103341362151)で、
通常Hostからの起動と結果確認が成功しました。
割り当ては7,964,983,296から4,224,712,704 バイトへ減少し、**3,740,270,592 バイトを回収**しました。
仮想容量1 TiBとIncus プール容量128 GiBは不変で、Linux discard、正確なWSLの停止・圧縮・再開、
Host 識別情報、未接続Workspace・OCI・スナップショットの復元を確認しました。

一つのCI構成での結果であり、すべての既存導入先を確認したものではありません。
以前のJob・open・起動失敗は失敗のままで、原因がすべて判明したわけではありません。
一部のWindows native検証では権限不足でsymlink作成を省略し、junction拒否は確認しました。
電源喪失、別ユーザー・セッション、すべての外側Job、実worker中断後の再確認は未確認です。
[受入記録](../status/acceptance-evidence.ja.md#storage)に過去の結果と区別を残します。

リポジトリの回帰テストは実体置換、不正な記録、順序、部分失敗、再実行拒否、中断、証拠保持を対象にします。
`HACO_E2E_RECLAIM_TRIM=1` は所有する専用Btrfs 検証用構成、
`HACO_E2E_RECLAIM_OUTER_TRIM=1` は追加で専用WSLの外側FSを許可します。
無関係な共有Hostで有効にしないでください。
