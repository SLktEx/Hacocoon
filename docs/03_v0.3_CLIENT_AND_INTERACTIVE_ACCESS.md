# v0.3 — Client & Interactive Access

## Goal

Make a Hacocoon Environment comfortable for a human developer without making any single IDE part of Core.

## In scope

- Environment inspect/status suitable for clients.
- SSH access where appropriate.
- VS Code Remote-SSH workflow as the primary documented client path.
- code-server usage pattern where useful.
- Local-development port forwarding/exposure needed to reach services in an Environment.
- Stable client-facing identifiers and connection information.
- Clear separation between Client adapters and Environment implementation.

## Port boundary

v0.3 may provide the **connection mechanism**, but it must default to local/safely scoped access. Broad network exposure, sensitive port publication, or exceptions that require an authorization decision belong behind the v0.4 Policy/Capability boundary.

Do not invent a second approval system inside the client/port layer.

## VS Code rule

VS Code is a first-class **client**, not the Hacocoon UI architecture.

No VS Code extension should be created merely to duplicate capabilities already provided by Remote-SSH, standard terminals, ports, or browser mechanisms. Extension work remains optional and demand-driven.

## Other clients

JetBrains or another IDE can be added later if it can consume the same Environment/connection boundary. Hacocoon Core must not branch on IDE brand.

## Not in scope

- GitHub security capability.
- Policy decisions for privileged external exposure.
- AI orchestration.
- Proprietary editor/chat UI.
