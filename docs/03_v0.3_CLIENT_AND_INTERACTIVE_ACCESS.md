# v0.3 — Client & Interactive Access

## Goal

Make a Hacocoon Environment comfortable for a human developer without making any single IDE part of Core.

## In scope

- Environment inspect/status suitable for clients.
- SSH access where appropriate.
- VS Code Remote-SSH workflow as the primary documented client path.
- code-server usage pattern where useful.
- Minimal port-forward/exposure mechanism needed for local development.
- Stable client-facing identifiers and connection information.
- Clear separation between Client adapters and Environment implementation.

## VS Code rule

VS Code is the first-class **client**, not the Hacocoon UI architecture.

No VS Code extension should be created merely to duplicate capabilities already provided by Remote-SSH, standard terminals, ports, or browser notifications. Extension work remains optional and demand-driven.

## Other clients

JetBrains or another IDE can be added later if it can consume the same Environment/connection boundary. Hacocoon Core must not branch on IDE brand.

## Not in scope

- GitHub security capability.
- AI orchestration.
- Proprietary editor/chat UI.
