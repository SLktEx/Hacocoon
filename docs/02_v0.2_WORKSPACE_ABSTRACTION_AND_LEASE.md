# v0.2 — Workspace Abstraction & Lease

## Goal

Separate **where a Workspace came from** from **how Hacocoon safely lends it to an Environment**.

## In scope

- Formal `WorkspaceProvider` boundary.
- `WorkspaceLease` lifecycle.
- `ExternalPathWorkspace` as the baseline provider.
- Directory metadata and normalized identity.
- Minimal guard against accidental concurrent read/write use of the same workspace.
- Cleanup/recovery semantics for leases.
- Optional `GitWorktreeWorkspace` convenience provider.

## WorkspaceLease model

Conceptually:

```text
WorkspaceLease
- workspace_id
- source_path
- environment_id
- access_mode: ro | rw
- owner
- lifetime/state
```

Do not require all fields to become public API if the implementation can remain simpler.

## Worktree boundary

A Git worktree is **one way to produce a workspace**, not a Hacocoon Core concept.

When an external orchestrator creates worktrees:

```text
Daintree/Rookery -> worktree path -> ExternalPathWorkspace -> Hacocoon
```

When Hacocoon is used standalone, an optional provider may create a worktree:

```text
Human/CLI -> GitWorktreeWorkspace -> Workspace -> Hacocoon
```

The Environment/runtime path must behave the same in both cases.

## Not in scope

- Agent scheduling/model routing.
- GitHub credentials or push approval.
- IDE-specific workflow.
- Cloud runtime.
