# v0.17 — Docker Compatibility Plugin

Status: **foundation実装済み。complete plugin integrationはfollow-up。**

v0.17ではDocker compatibilityをoptionalなplugin/integration機能として扱います。Hacocoon CoreはEnvironment/executionを管理し、Docker EngineをCore runtimeにはしません。

## Runtime direction

標準runtime:

```text
containerd + nerdctl
```

compatibility path:

```text
normal       -> nerdctl -> containerd
compatibility -> genuine Docker CLI -> optional/on-demand dockerd -> existing containerd where supported
```

Docker CLI/Engine APIを要求するtoolを動かすための互換層であり、全Environmentで常時2つ目のdaemon/image storeを持つための機能ではありません。

## Plugin boundary

- Docker/nerdctl固有のorchestrationはCore外のplugin/adapterに置く
- genuine Docker CLIはcompatibility用に利用可能
- `dockerd`を常駐必須にしない
- Docker Engine APIが必要な場合だけexplicit/on-demand起動
- compatibilityだけを理由にOCI image layerを二重化しない
- coding agentへHacocoon/Incus host authorityを渡さない

## Current repository reality

現在はDocker compatibility designとsystemd socket/service packaging foundationまで実装されています。full v0.17 plugin完成とはまだ扱いません。

plugin boundary、lifecycle wiring、runtime validation、supported-host testが揃った時点でcompleteへ進めます。

## Non-goals

containerd/nerdctlの置換、Docker Engine必須化、不要時のdockerd常駐、理由のないimage store二重化、Docker固有概念のCore化は行いません。
