# v0.17 — Docker Compatibility Plugin

[English](17_v0.17_DOCKER_COMPATIBILITY_PLUGIN.md) | **日本語**

Status: **plugin境界とdriver compositionは実装済み。Docker Engine/Base統合とreal-host acceptanceはfollow-up。**

v0.17ではDocker compatibilityをoptionalなplugin/integrationとして扱います。Hacocoon CoreはEnvironment/executionを管理しますが、Docker Engine、containerd、nerdctlをCore runtime dependencyにはしません。

## Hacocoonが用意するOCI profile

OCI workflowを使う場合、project-maintained profileとして主に想定するのは:

```text
containerd + nerdctl
```

です。ただしこれは**profile選択**であってCoreの不変条件ではありません。Base/Seedは別のOCI stackを提供してもよく、OCI tooling自体を持たなくても構いません。

Docker compatibilityはそのprofileへの追加経路です。

```text
normal profile -> nerdctl -> containerd
compatibility  -> genuine Docker CLI -> optional/on-demand dockerd -> existing containerd where supported
```

## Plugin boundary

OCI/container固有実装は`modules/plugin/oci`に置き、明示的にcompositionします。

```text
HACO_PLUGIN_OCI=nerdctl
HACO_PLUGIN_OCI=docker
```

未設定ならOCI pluginは存在せず、Coreはcontainer toolingをprobeしません。

現在のrepositoryには次が入っています。

- nerdctl/Docker inventory driverの明示選択
- OCI telemetry/recommendation/deletion stateの`modules/plugin/oci`所有
- Docker compatibility systemd unitの`modules/plugin/oci/packaging/systemd`所有
- Docker driverを選んだだけでは任意のHost Docker daemonを操作できないauthority boundary

## Docker Engine compatibility

Docker ecosystem互換のため本物のDocker CLIを提供できますが、`dockerd`をHacocoon常駐必須にはしません。

Engine compatibilityを提供するprofileでは、想定lifecycleは次です。

```text
Docker API client
      |
 /run/docker.sock
      |
socket activation
      v
    dockerd
      |
 Environment-local existing containerd where supported
```

必須rule:

- Engine APIが必要なworkloadだけexplicit/on-demand起動
- socketはEnvironment-local
- Host Docker socketをEnvironmentへmountしない
- Docker compatibilityからHacocoon/Incus Host authorityやreusable credentialを得られない
- compatibilityだけを理由に2つ目のHacocoon-managed containerd/image storeを作らない

## Current completion boundary

plugin/package境界、driver composition、systemd packaging ownershipまでは実装済みです。official Base/Seed bake-in、完全なon-demand Engine lifecycle、supported-host validationが未完なのでv0.17はpartialのままです。

## Non-goals

OCI toolingのCore必須化、Docker Engine必須化、不要時の`dockerd`常駐、Host Docker socket公開、Docker/containerd/nerdctl固有概念のCore化は行いません。
