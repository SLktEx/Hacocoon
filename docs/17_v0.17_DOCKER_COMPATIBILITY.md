# v0.17 — Docker Compatibility

Status: **optional-plugin packaging foundation implemented; Base/Seed integration and real-host lifecycle acceptance remain pending.**

Docker is a compatibility interface, not the Hacocoon Core runtime.

The project-maintained OCI plugin may use a `containerd + nerdctl` profile. Where developer tooling requires genuine Docker semantics, the optional Docker profile can provide the real Docker CLI and an Environment-local Docker Engine compatibility path.

```text
Docker CLI / API client
        |
/run/docker.sock
        |
plugin-owned systemd socket activation
        |
      dockerd
        |
existing Environment containerd
```

## Rules

- Core must work with `HACO_PLUGIN_OCI` unset and must not require Docker/nerdctl/containerd merely to manage Environments.
- Use the genuine Docker CLI rather than a Hacocoon command wrapper.
- `dockerd` is not a mandatory always-on Hacocoon daemon.
- Docker compatibility must never mount the Host Docker socket into an Environment.
- Docker API stays Environment-local by default.
- A Docker-socket user is root-equivalent inside that Environment and is treated accordingly.
- Shared OCI content does not imply zero total storage duplication; namespace metadata, snapshots, writable layers and caches can consume additional space.

Detailed design: [`OCI_RUNTIME_AND_DOCKER_COMPAT.md`](OCI_RUNTIME_AND_DOCKER_COMPAT.md).
