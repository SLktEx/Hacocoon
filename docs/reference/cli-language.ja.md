## 言語を選ぶ

`HACO_UI_LANGUAGE=en`または`HACO_UI_LANGUAGE=ja`で、OS localeを変えずに
Hacocoonの表示を選べます。空でない未対応値は英語になります。この指定が空なら、下記の
POSIX設定を使います。Host入場時には判定済みの`en`／`ja`だけをそのshell sessionへ渡し、
通常Envのshellへは転送しません。[ADR 0065](../adr/0065-host-presentation-language.md)を参照してください。

製品CLIは `LC_ALL` → `LC_MESSAGES` → `LANG` の順に、最初の空でない値を使います。`ja`、`ja_JP.UTF-8`、`ja-JP` などの日本語ロケールでは日本語になります。英語、`C`、`C.UTF-8`、`POSIX`、未対応・不正な値、すべて未設定の場合は英語になります。上位に未対応の値がある場合、下位の日本語設定には進みません。空文字は飛ばしますが、空白文字だけの値は空文字ではありません。

表示言語の判定にOSのロケール導入は不要です。Linux/WSLで上位の指定を解除し、1回だけ日本語にする例:

```bash
HACO_UI_LANGUAGE=ja haco help
```

1回だけ英語に固定する例:

```bash
HACO_UI_LANGUAGE=en haco help
```

今回の実装では、Windowsで `$env:LANG` を設定するだけでは自動的に引き継がれません。Linux側のCLIに明示的に指定する例:

```powershell
wsl -d Hacocoon --exec env HACO_UI_LANGUAGE=ja haco host shell
```

ディストリビューション名が異なる場合は `Hacocoon` を実際の名前に置き換えます。これは設定例であり、Windows実機での動作確認結果ではありません。言語判定は環境変数を設定せず、OS・WSL・Environment・子プロセスのロケールを永続的に変更しません。[Host入場時の言語](../design/trusted-host.md#host-entry-language)で説明する既存のインストーラーの動作は変更しません。

## 対応した画面

- トップレベルのヘルプ、不明なコマンド・引数の案内、人向けの `haco version` 表示。
- Host権限の警告。端末での色表示とリダイレクト時の通常表示を維持します。
- `haco approve` のヘルプ、操作の選択、承認の選択肢、結果、保存した承認ルールの説明。
- `haco env` の全体の使い方、create/SSHのオプション説明、この入口が直接出す接続・出力エラー。
- `haco env list` と `haco env status` の人向け表示。見出し、一覧が空の場合の案内、接続コマンド、停止中の開発環境で作業データを保持している旨の案内。
- `haco doctor` の人向け表示。見出し、既知の環境内チェックに対する次の操作、接続のラベル、診断していない範囲の明示。別の言語で表示しても追加の検査や修復は行いません。
- `haco env copy`、`haco env import`、`haco env export` の使い方、JSONオプションの説明、直接出す接続・出力エラー、完了・データ保持の案内、元のエラーに添える失敗の説明。
- `haco doctor` の使い方、診断の見出し、次の操作を示すラベル。コントローラーが返す詳細はそのままです。

## 互換性と境界

コマンド名・オプション名・入力の解釈・リソースの識別子・設定キー・JSONの形式と値・操作の判断・stdout/stderrの使い分けは表示言語で変わりません。現在JSON文字列として出力されるEnvironment操作の完了メッセージ、承認の一覧・結果、`version --json` も同様です。短い `--version` 表示と生成するSSH設定はそのままです。

Environmentの状態・アクセス方式、診断項目名・状態のトークンは翻訳しません。Environment診断のJSONに含まれる `action` と `scope` の文章は既存の英語表現を維持します。非公開の表示用情報によって日本語の説明を選び、レポートの値を書き換えません。未知のレポートの詳細は原文を維持し、文字列の内容から翻訳を推測しません。

人向けのEnvironment表示と転送結果は、名前・パス・表示する結果の値に含まれる非表示文字を端末向けにエスケープします。リソース名やJSONの値自体は変更しません。一覧はコピーを並べ替えて表示し、呼び出し元のデータ順序を変えません。Git/SSH/OS/バックエンドの元のエラーは詳細としてそのまま残し、翻訳フィルターには通しません。

言語選択によって操作の成否や承認の終了コードは変えません。Environment診断の表示には、別途小さな出力エラー修正も含みます。最初の見出しより後で出力が失敗した場合も、無視せず日英とも既存の失敗コード `1` を返します。

承認の入力は従来の `y`/`yes`、`N`、番号を使います。空欄や不明な入力では許可しません。「毎回確認する」ルールを保存しても、今回の実行は別途回答が必要です。端末向けのエスケープを維持し、表示に失敗した場合は許可しません。承認画面には言語を値として渡し、追加の確認でも同じ言語を使います。従来のコンストラクターを使う別の呼び出し元は英語のままです。

共通辞書は信頼されたメッセージIDの文章を選び、その後で値を埋め込みます。出力全体を変換する
仕組みではなく、コントローラーに可変の表示言語を持たせません。Host-shell要求に検証済みの
表示用の値を追加し、そのsessionだけに適用します。任意の環境変数の転送やゲスト設定の永続変更は行いません。

## 残っている範囲

ほかのコマンド群やEnvironmentの下位処理の案内は、辞書への移行が残っています。標準ライブラリの引数解析エラー、Git/SSH/OSの元のエラー、構造化ログ、コントローラーの診断詳細・対処内容はそのままです。これらの詳細に日本語の説明を添える追加対応は今後の作業です。

WSLからHostへの正規化済み表示言語の引き継ぎは実装済みです。Windowsの言語自動選択、
Windows/WSLとIncusの実機受け入れ、全コマンド対応は残っています。
この部分実装でIssue #577を完了扱いにしません。

## 検証

言語判定・辞書のテストは、ロケールの優先順位、不正値、英語へのフォールバック、日英の埋め込み値の一致、辞書間のID重複、呼び出し側の固定メッセージID、引数の保持、日英の独立した並行処理を確認します。ロケール解析にはfuzzテストもあります。

製品CLIと承認処理の回帰テストには、JSON・終了コード・承認範囲・未入力時の拒否・追加の確認・端末向けエスケープ・表示失敗を含めています。Environment用の追加テストは、元データを変えない一覧の並べ替え、状態値、診断とコピーのJSON一致、検査内容の不変、元のエラーの保持、転送コマンドの使い方、英語の対処案内との互換性、診断の各出力箇所での失敗を確認します。

リポジトリ全体のCI、文書チェック、実機受け入れの結果は関連PRに別途記録します。部分チェックアウトでの言語判定・辞書のraceテストとvetだけで、製品パッケージのコンパイル、全体検証、導入済みWindows/WSLの動作確認が済んだとは扱いません。

## 統合候補の追加対応

M0候補は#580の既存辞書を再利用し、現行の階層別ヘルプと日常操作の失敗・保持データ・

撤去しました。Host sessionへ正規化した表示言語を渡す処理は実装済みで、Windowsの
言語自動選択は残件です。
