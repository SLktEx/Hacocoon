# v0.18 — Docker Compatibility Plugin

[English](18_v0.18_DOCKER_COMPATIBILITY_PLUGIN.md) | **日本語**

Status: **milestone順より先にrepository実装完了。real-host acceptanceは環境依存で別途。**

v0.18はDocker互換をoptional OCI plugin機能として扱います。Hacocoon CoreはEnvironmentとExecutionを扱い、Docker Engine / containerd / nerdctlを必須にしません。

この実装は、このfeatureがv0.17と呼ばれていた時点で先にlandしました。現在の正本ではEnvironment/Base/Seed側の流れを先に置くため、v0.17をOCI Seed Builder & Btrfs/COW、v0.18をDocker Compatibilityとします。historical commit/PRには旧番号が残る場合があります。

## Maintained OCI profile

project-maintained OCI plugin profileでは `containerd + nerdctl` を使えます。これはCore invariantではありません。

Docker互換は追加機能です。

```text
maintained profile -> nerdctl -> containerd
compatibility      -> genuine Docker CLI -> optional/on-demand dockerd -> existing containerd where supported
```

## Commands

`HACO_PLUGIN_OCI=docker` を選んだ場合だけDocker lifecycle commandを公開します。

```text
haco plugin oci docker status <environment> [--json]
haco plugin oci docker prepare <environment> [--json]
```

`status` は観測だけを行い、`dockerd` を起動しません。

`prepare` は意図的に狭く、idempotentです。

1. trusted Hacocoon stateからmanaged Environmentを解決する
2. genuine `docker` CLI、`dockerd`、`containerd`、systemd、`docker` groupを確認する
3. installed `hacocoon-docker.socket` / `.service` がpluginにpinされたunitと完全一致することを確認する
4. vendor Docker daemon/socketが既にactiveなら勝手に停止せずfail closedする
5. inactiveなvendor Docker autostartだけdisableする
6. `hacocoon-docker.socket` だけをenable/startする
7. 再probeして期待したsocket-activated stateでなければfail closedする

`prepare` はpackage install、image pull、Host socket mount、既存guest Docker daemonのsilent stopを行いません。必要なDocker compatibility profileとpinned unitはBase/Seed側で提供します。

`hacocoon-docker.service` がinactiveでも正常です。Environment-local clientが `/run/docker.sock` を開いた時だけEngineがon-demand起動する想定です。

## Plugin boundary

- Docker/nerdctl固有処理は `modules/plugin/oci` / `haco plugin oci` に置く
- `HACO_PLUGIN_OCI=nerdctl|docker` で明示opt-in。未設定ならOCI pluginなし
- dockerdをalways-on要件にしない
- EngineはEnvironment-localかつsocket activationで必要時起動する
- Host Docker/containerd/Incus/Hacocoon control socketをmountしない
- Docker APIのTCP listenerをdefaultで公開しない
- complete byte-level deduplicationは保証しない

## Repository gate

plugin-owned systemd packaging、lifecycle/status service、CLI integration、unit driftのfail-closed検証、unit testまでrepository gateとして実装済みです。real-host acceptanceは別で、実際のBaseが必要binary/unitを持ち、対象Incus/systemd環境でsocket activationが動作することの確認は環境依存です。

## v0.17との関係

v0.17はphysical OCI Seed build/publish/COW lifecycleを担当します。v0.18のrepository実装自体はSeed Builderなしでも存在できますが、`docker prepare` が検証するbinary/pinned unitをproject-maintained Environment profileが提供する流れを先に整理するため、roadmap上はSeed/Base側をv0.17に置きます。

## Non-goals

- containerd / nerdctlをCore requirementにすること
- Docker Engineをmandatoryにすること
- dockerdを常駐させること
- Host Docker/containerd socketを公開すること
- `haco plugin oci docker prepare` からDocker packageをinstall/updateすること
- Docker固有概念をCoreへ持ち込むこと
