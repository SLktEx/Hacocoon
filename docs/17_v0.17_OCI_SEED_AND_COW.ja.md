# v0.17 — OCI Seed Builder & Btrfs/COW Optimization

[English](17_v0.17_OCI_SEED_AND_COW.md) | **日本語**

Status: **first repository slice実装済み / partial。v0.15 recommendationとv0.16 deletion policyは実装済みprerequisiteです。Seed build/publish、exact-parent resolution、explicit operator Seed pin/re-enable selectionまで実装され、real-host / physical COW acceptanceが残っています。**

v0.17はphysical OCI Seed pipelineを担当します。trusted Host-side image acquisition/cache、offline Seed construction、immutable publication、revision pinning、storage-driver COW benefitを一つのfeature gateとして扱います。

Local Registryは必須ではありません。

この実装は、このfeatureがv0.18と呼ばれていた時点でlandしました。現在の正本ではSeed Builder/COWをv0.17へ付け替えます。historical commit/PRには旧番号が残る場合があります。

## Goal

common OCI imageをimmutable Incus-derived Seedへpreloadし、normal Incus/storage-driver clone semanticsでunchanged filesystem blockを再利用しつつ、各Environmentのwritable containerd stateは独立させます。

```text
upstream registry
      |
 trusted Host acquisition/cache
      v
Host seed cache
      |
 OCI export/stream
      v
Offline Seed Builder
(no general network; no NIC)
      |
containerd import/unpack
      |
clean stop
      v
immutable Incus Seed
      |
Incus clone / Btrfs COW
      v
independent Environments
```

- Tooling Base / current Seed manifestのpersistとprocess-safe build lock
- build前のimmutable parent Base resolution
- dedicated `hacocoon-seed` namespaceを使うtrusted Host-side OCI acquisition
- profileなし・NICなしのoffline Seed Builder

## Mandatory isolation

storage savingのために複数Environmentで一つのwritable `/var/lib/containerd` を共有してはいけません。各Environmentはindependentにmutable/deletable/recoverableである必要があります。

## Inputs

- v0.11のimmutable parent Base revision
- v0.15 recommendation/auto-promotion + explicit operator input
- v0.16 deletion tombstone/override
- authenticationが必要な場合のtrusted Host-side upstream credential

mutable OCI tagはinput convenienceであり、Seed manifestはimmutable digestをpersistします。operatorがSeed selectionを明示変更する場合は、完全なimmutable `reference@sha256:...` identityを要求します。

## Operator selection precedence

operatorのpin/re-enable stateはsampled usage stateとは別にpersistします。これにより明示selectionがtelemetryを書き換えたり、deletion historyを消したりしません。

- 通常の `seed pin` はautomatic top-10% promotionの外にあるimmutable identityでもfuture Seed対象へ含めます。ただし `pinned=true` と `auto_promote=true` は別の意味のまま保持します。
- 現在tombstoneで削除扱いのidentityは暗黙にpinできません。operatorは `seed re-enable` または `seed pin ... --re-enable` を明示する必要があり、re-enableは既存deletion tombstoneがあるidentityにだけ許可します。
- re-enableはtombstoneを削除しません。より新しいoperator decisionとして記録します。その後さらに新しいdeletionが記録された場合は、そのlater deletionが再び勝ち、古いpinが残っていてもidentityを抑止します。
- `seed unpin` が削除するのはpinだけです。re-enable decisionやdeletion historyは消しません。
- pin/re-enableが変更するのはfuture Seed selectionだけです。registry/network/Host credential/provider/Environment authorityは一切付与しません。trusted Host acquisitionとcredential policyは独立して適用され、reusable credentialをSeed BuilderやSeedへコピーしてはいけません。

この優先順位により、destructive decisionはfail closedのまま、operator intentは監査可能な履歴として残り、覆す時にも明示的なlater actionを要求します。

## Build lifecycle

1. Baseをimmutable revisionへresolve
2. OCI recommendationとexplicit operator selectionからeffective Seed image setを確定
3. trusted HostでOCI contentをacquireしdigest pin
4. temporary Seed BuilderへOCI export/stream
5. pinned Tooling Baseからgeneral networkなし・NICなしでbuilder作成
6. supported containerd/nerdctl interfaceでimport/unpack
7. requested digestをverify
8. containerd/Docker compatibility serviceをclean stop
9. builder stop
10. immutable Incus Seed revisionをpublish
11. Base / Tooling / Seed revisionとOCI digest manifestをpersist
12. publication/validation成功後のみcurrent-Seed pointerをmove
13. publication/state persistenceが曖昧ならrecovery-required

## Plugin boundary

Seed observation/deletion/build/currentとoperator selectionは `haco plugin oci ...` 配下です。v0.17のphysical builder/publisherもCoreへOCI/containerd/nerdctl/Incus/Btrfs vocabularyを持ち込まず、OCI/provider adapter boundaryに置きます。

## Btrfs/COW boundary

HacocoonはIncus/storage-driver cloningを利用し、CoreからIncus-owned Btrfs subvolumeを直接操作しません。Btrfsではunchanged blockのCOW sharingを期待できますが、non-COW backendでは同等のphysical savingをclaimしません。

## Security requirements

- shared writable containerd root禁止
- coding Environment/Seed BuilderへのHost containerd/Docker socket禁止
- Incus/Hacocoon control socket禁止
- Seed Builderのarbitrary upstream network禁止
- network acquisitionはtrusted Host側
- credentialをSeedへ埋め込まない
- operator pin/re-enableはacquisition/network/credential authorityを付与しない
- partial buildをcurrentにしない
- cleanup ambiguityはrecovery-required
- old Seed GCはactive/recoverable Environmentが依存し得るrevisionを保守的に保持

## 残るacceptance / follow-up

first repository sliceだけではv0.17 completeではありません。残件は次です。

- real supported-host Incus + containerd + nerdctl acceptance
- Tooling Base pathのreal Docker Engine compatibility acceptance
- conservative old Tooling/Seed revision GCとrestart/crash recovery
- credential leakなしのauthenticated/private-registry combinations
- physical Btrfs COW/block-sharing measurement
- publish/cleanup/state persistenceのbroader failure-injection coverage
