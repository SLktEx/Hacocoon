# v0.10 Per-Agent Sandbox & Agent Host Integration

**Status:** broker foundation implemented on 2026-08-29  
**Compatibility:** pre-1.0; interfaces and integration details may change incompatibly.  
**Real routing acceptance:** real VS Code Agent Host/AHP + Incus routing acceptance pending.

## Goal

v0.10 adds a trusted client-integration path that binds each independently routable coding-agent session to its own Hacocoon Environment without giving the coding agent Hacocoon or Incus control-plane authority.

```text
VS Code Agents UI / trusted client
                 |
       trusted integration
                 |
        per-session broker
                 |
        +--------+--------+
        |                 |
  Environment A      Environment B
     Incus A            Incus B
        |                 |
   Agent Host A       Agent Host B
        |                 |
     Agent A             Agent B
```

Hacocoon remains a Secure Workspace Runtime. It does not become an AI scheduler, task planner, model router, or chat product.

## Security boundary

An agent Environment must not receive merely for convenience:

- the Incus Unix socket or equivalent administrator authority;
- Hacocoon state or management/control access;
- host-side Hacocoon credentials;
- broad GitHub, AWS, cloud, or host credentials;
- authority to create, select, or delete arbitrary sandboxes.

`haco` remains a human/operator and trusted-automation interface. The coding agent is not expected to invoke it to manage its own sandbox.

## Broker contract

`internal/agenthost` lives outside Core and reuses the existing Environment and WorkspaceLease lifecycle.

Conceptual input:

```text
opaque external session identity
Workspace path
Access mode
```

The broker requires:

1. a session identity selects one Environment identity;
2. raw session IDs are not stored or used directly as runtime instance names;
3. exact reacquire is idempotent;
4. Workspace/access-mode rebinding fails closed;
5. session-to-Environment binding is persisted in trusted control-plane state;
6. release requires persisted binding proof and cannot delete an arbitrary deterministic-name Environment;
7. existing WorkspaceLease rules remain authoritative.

A deterministic Environment name is not sufficient proof of ownership. If an Environment exists but no persisted agent binding proves that it belongs to the session, the broker refuses to adopt or delete it.

## Parallel agents and worktrees

Parallel read/write sessions must not share one canonical host directory. They should normally receive separate Git worktrees:

```text
repository
  +-- worktree/session-a -> Environment A -> Agent A
  +-- worktree/session-b -> Environment B -> Agent B
```

Git worktrees isolate code changes. Incus Environments provide OS/runtime security isolation. Worktree creation remains outside Hacocoon Core.

## Relationship to v0.9 Base images

v0.10 composes with the v0.9 Base Images & Custom Environments contract rather than replacing it.

```text
trusted session integration
        |
    session binding
        |
  EnvironmentSpec
   /          \
Workspace    Base
   \          /
    Environment
```

When Base selection is implemented, a per-agent Environment must use the normal Base-resolution path and must not bypass immutable Base-revision or provider-policy rules.

## VS Code Agent Host / AHP

The preferred VS Code direction is to run the Agent Host next to the assigned Workspace inside the Environment and keep Agent Host Protocol details at the client-integration boundary.

AHP is an external protocol and must not become Core vocabulary. Lifecycle hooks may help observation or cleanup, but hooks alone are not proof that execution moved into Incus; the execution host itself must actually run inside the assigned Environment.

The initial ownership unit is an **independently routable top-level agent session**. Hidden harness-internal subagents may share the parent Environment unless the client exposes a separate routable lifecycle.

## Existing behavior remains

v0.10 is additive. These paths remain available:

```text
haco create / exec / shell / delete
haco run
haco-vscode open / delete
```

## Acceptance gate

Repository acceptance requires:

- persisted per-session binding outside Core;
- distinct session identities -> distinct Environment identities;
- exact reacquire idempotence;
- Workspace/access-mode rebind rejection;
- raw session ID non-disclosure in Environment names/state;
- release refusal without persisted ownership proof;
- restart-safe lookup from persisted state;
- existing WorkspaceLease safety unchanged;
- build, vet, race, docs consistency, and existing tests green.

Environment-dependent acceptance requires a real supported Incus + current VS Code Agent Host/AHP setup and must verify two independent agent sessions remain isolated across execution, reconnect, and cleanup.

## Non-goals

v0.10 does not own model selection, task decomposition, retries, token budgets, AI chat UI, Git branch strategy, automatic merge/review, AHP replacement, or hidden-subagent scheduling.

## One-sentence definition

> **v0.10 binds each independently routable coding-agent session to a dedicated Hacocoon Environment while keeping Hacocoon and Incus control authority outside the agent sandbox.**
