# v0.15 — OCI Seed Recommendation

Status: **implemented on `main`; physical Seed build/publish remains v0.18.**

v0.15 makes future OCI Seed selection evidence-based while keeping OCI/containerd/nerdctl-specific operations outside Core under the optional OCI plugin namespace.

## CLI

```text
haco plugin oci seed sample
haco plugin oci seed recommend
```

The removed pre-1.0 `haco image ...` namespace is not retained as an alias. Hacocoon Environment starting points use `haco base ...`; OCI/container-image lifecycle uses `haco plugin oci ...`.

## Telemetry model

The trusted Host stores the latest OCI image snapshot per Environment. The snapshot contains only Seed-selection identity data:

- Environment identifier;
- sample timestamp;
- repository/reference;
- tag when present;
- immutable digest when observable.

It does not collect command history, container output, registry credentials, credential-helper responses, or Workspace contents.

Current defaults:

- snapshots newer than 6 hours are considered fresh for opportunistic sampling;
- recommendations consider snapshots from the most recent 30 days;
- repeated sampling of one Environment does not increase its weight because only the latest snapshot per Environment is counted.

## Immutable recommendation identity

Seed recommendations require an observed immutable digest. A mutable tag alone is not sufficient identity.

Recommendation identity is effectively:

```text
reference@sha256:...
```

A tag moving to a new digest creates a different recommendation identity.

## Automatic promotion

Eligible recommendations are ranked deterministically and the top **10%** are marked `auto_promote=true`.

```text
eligible recommendations   automatically promoted
1-10                       1
11-20                      2
21-30                      3
...
```

The count is `ceil(eligible_count * 0.10)` with a minimum of one when at least one eligible recommendation exists.

Ranking order:

1. number of recent Environments containing the exact image identity, descending;
2. most recent observation, descending;
3. image reference, ascending;
4. digest, ascending.

Human-readable recommendation output marks automatically selected entries as `auto`; JSON exposes `auto_promote`.

## Safety boundary

Automatic promotion selects OCI image content, not credentials or arbitrary Environment data.

- Host/registry credentials are never promoted into a Seed.
- Workspace files are not part of telemetry or Seed recommendation state.
- A failed sample is surfaced rather than silently treated as an empty Environment.
- Images without immutable digests cannot be automatically selected.
- Selection does not mutate existing Environments or already-published immutable Seeds.
- v0.16 deletion tombstones override recommendation/automatic promotion for the exact deleted identity.

## Relationship to v0.18

v0.15 decides **what should go into a future Seed**. v0.18 owns trusted Host-side acquisition/cache, offline Seed Builder import/unpack, immutable publication, current-Seed pointer movement, and Btrfs/COW integration. A Local Registry is not a prerequisite.
