# v0.18 — OCI Seed Builder & Btrfs/COW Optimization

Status: **repository slice実装中 / partial。v0.15 recommendation、v0.16 deletion policy、Seed build/publish、exact-parent resolution、explicit operator Seed selection overrideは実装済みです。real-host / physical COW acceptanceは残っています。**

v0.18はphysical OCI Seed pipelineを担当します。trusted Host-side image acquisition/cache、offline Seed construction、immutable publication、revision pinning、storage-driver COW benefitを一つのfeature gateとして扱います。

Local Registryは必須ではありません。

## Goal

common OCI imageをimmutable Incus-derived Seedへpreloadし、normal Incus/storage-driver clone semanticsでunchanged filesystem blockを再利用しつつ、各Environmentのwritable containerd stateは独立させます。

```text
upstream registry
      |
 trusted Host acquisition/cache
      v
Host seed cache
      |
 OCI export/stream
      v
Offline Seed Builder
(no general network; no NIC)
      |
containerd import/unpack
      |
clean stop
      v
immutable Incus Seed
      |
Incus clone / Btrfs COW
      v
independent Environments
```

- `haco plugin oci seed pin <reference@sha256:...> [--re-enable] [--json]`

- `haco plugin oci seed re-enable <reference@sha256:...> [--json]`
- Tooling Base / current Seed manifestのpersistとprocess-safe build lock
- build前のimmutable parent Base resolution
- dedicated `hacocoon-seed` namespaceを使うtrusted Host-side OCI acquisition
- profileなし・NICなしのoffline Seed Builder
- live containerd state directoryをcopyせず、supported nerdctl/containerd interfaceでimport
- publish前の全selected immutable digest verification
- immutable Incus image publish前のservice clean stop
- publicationとmanifest persist成功後だけcurrent-Seed pointerをadvance
- recorded parent Base revisionがcurrent immutable parentと一致する時だけSeedを使うexact-parent resolution

## Mandatory isolation

storage savingのために複数Environmentで一つのwritable `/var/lib/containerd` を共有してはいけません。各Environmentはindependentにmutable/deletable/recoverableである必要があります。

## Inputs

- v0.11のimmutable parent Base revision
- v0.15 recommendation/auto-promotion + explicit operator pin
- v0.16 deletion tombstone + explicit re-enable decision
- authenticationが必要な場合のtrusted Host-side upstream credential

mutable OCI tagはinput convenienceであり、Seed manifestとoperator selection stateはimmutable digestをpersistします。

## Operator Seed selection

operator selection stateはusage telemetryと分離して `state/oci-selections.json` にpersistします。保存するのはimmutable image identityとtimestampだけで、registry credential、credential-helper output、provider output、Environment fileは保存しません。

```text
haco plugin oci seed pin <reference@sha256:...>
haco plugin oci seed unpin <reference@sha256:...>
haco plugin oci seed re-enable <reference@sha256:...>
haco plugin oci seed pin <reference@sha256:...> --re-enable
```

`pin` は「automatic promotionの順位外でも、このimmutable identityを次のSeed selectionに含める」というoperator intentです。pinを `auto_promote=true` と偽装しません。Seed buildは `auto_promote=true` とeffective pinのunionを選択します。

deletion tombstoneはautomatic recommendationだけでなく既存pinにも優先します。deleted identityを普通にpinしようとするとfail closedし、明示 `--re-enable` が必要です。`re-enable` 単体はpinせず通常rankingへ戻します。`pin --re-enable` は復活とpinを一操作で記録しますが、実際にtombstoneが存在するときだけ許可します。

precedenceはtimestampで決まり、fail closedです。

1. deletionでidentityをblock
2. そのdeletionより**厳密に後**のexplicit re-enableだけがblockを解除
3. さらに後のdeletionがあれば再びblock
4. `unpin` はpinだけを外し、re-enable decisionやdeletion historyは消さない

つまり復活のためにtombstoneを削除しません。壊れた/未知versionのselection stateは黙ってenableせずfail closedします。

pin/re-enableはあくまで**selection intent**です。network access、Host acquisition policy、registry credentialを許可するものではなく、Seed Builderへcredentialを渡す理由にもなりません。trusted Host acquisition pathは従来どおりのauthority boundaryでimmutable contentを取得・検証する必要があります。

## Build lifecycle

1. Baseをimmutable revisionへresolve
2. recommendation / pin / deletion / re-enable precedenceからeffective Seed image setを確定
3. trusted HostでOCI contentをacquireしdigest pin
4. temporary Seed BuilderへOCI export/stream
5. pinned Tooling Baseからgeneral networkなし・NICなしでbuilder作成
6. supported containerd/nerdctl interfaceでimport/unpack
7. requested digestをverify
8. containerd/Docker compatibility serviceをclean stop
9. builder stop
10. immutable Incus Seed revisionをpublish
11. Base / Tooling / Seed revisionとOCI digest manifestをpersist
12. publication/validation成功後のみcurrent-Seed pointerをmove
13. publication/state persistenceが曖昧ならrecovery-required

## Plugin boundary

Seed observation/deletion/selection/build/currentは `haco plugin oci ...` 配下です。v0.18のphysical builder/publisherもCoreへOCI/containerd/nerdctl/Incus/Btrfs vocabularyを持ち込まず、OCI/provider adapter boundaryに置きます。

## Btrfs/COW boundary

HacocoonはIncus/storage-driver cloningを利用し、CoreからIncus-owned Btrfs subvolumeを直接操作しません。Btrfsではunchanged blockのCOW sharingを期待できますが、non-COW backendでは同等のphysical savingをclaimしません。

## Security requirements

shared writable containerd root禁止、coding Environment/Seed BuilderへのHost containerd/Docker socket禁止、Incus/Hacocoon control socket禁止、Builderのarbitrary upstream network禁止、network acquisitionはtrusted Host側、credentialをSeed/selection stateへ埋め込まない、pin/re-enableをacquisition authorizationとして扱わない、later deletionを優先、partial buildをcurrentにしない、cleanup ambiguityはrecovery-required、old Seed GCはconservativeにします。

## 残るacceptance / follow-up

repository sliceだけではv0.18 completeではありません。残件は次です。

- Environmentが既にauthenticated/private imageをpull済みの場合のcredential-free trusted harvesting
- Host-owned credentialを使うauthenticated/private-registry combinationのvalidation
- conservative old Tooling/Seed revision GCとrestart/crash recovery
- real supported-host Incus + containerd + nerdctl acceptance
- Tooling Base pathのreal Docker Engine compatibility acceptance
- physical Btrfs COW/block-sharing measurement
- Incus/Btrfs-backed trusted acquisition cacheがblock reuseを改善するかの測定
- publish/cleanup/state persistenceのbroader failure-injection coverage
